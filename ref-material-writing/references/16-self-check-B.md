# 自检标准档 B：JSON 卡片产出物

> 适用：step-02 `_card_[资料ID].json`、step-03 `_交叉引用结果.json`。
> 调用位置：step-02 / 03 [验证] 段；RESUME-CHECK 据本档判定（设计点 4）。

## 必过项

1. **存在性**：`FILE_STAT` 确认每个卡片文件存在。
2. **非空阈值初筛**：字节数 < 200B 视为明显损坏（JSON 至少含必填字段，不可能极小）。
3. **轻签名**：字节数 + 行数 vs [产出] 预期。
4. **结构完整性**：
   - `json.loads` 可解析（无语法错误）；
   - 必填字段齐全，对齐 `assets/analysis-card-template.json`：资料ID / 来源路径 / 资料类型 / 核心主题 / 核心结论 / 关键事实与数据 / 论点树 / 信息属性分类 / 关键段落位置 / 立场与局限 / 逻辑组织形式 / 内部自引用 / 读取状态；
   - 数组长度符合预期（卡片数 = 资料数；交叉引用条目数 ≥ 关联对数）。
5. **模型输出截断（B 类）**：JSON 未闭合（缺 `}` 或数组未闭合）→ 判 ❌。

## 回填 / 回退（设计点 6）

- 同 A 档：情形A 回填、情形B / C 回退重做。

## 完整性 vs 正确性

本档验 integrity；卡片内容正确性（如论点树逻辑）由 step-07 覆盖。

## 与 §14 衔接

- 本档验 **integrity**（存在 / 非空 / 结构完整）；卡片内容正确性（论点树逻辑 / 事实准确度）由 step-07 覆盖（设计点 8B）。
- step-02 / step-03 自检通过 → 向状态文件 §14 写入"✅通过 + 轻签名（字节数,行数）+ 登记对象=卡片绝对路径 + 子阶段（如 2/5 卡 / 全文）+ 自检时刻"；失败回退重做本步 [执行]→[产出]→[验证] 后重检（设计点 5/6）。
