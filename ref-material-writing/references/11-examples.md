# 示例集

> **触发场景索引**：本文件包含6个场景的完整示例。当遇到以下情况时加载：
> - 用户提供了类似的输入场景
> - 需要参考工作流执行步骤
> - 对某个步骤的执行方式存疑
> - 遇到 `12-edge-cases.md` 中引用的对应场景
> - 各步骤执行细则见 `_router/step-01.md` ~ `_router/step-10.md`

---

## 示例1：正常场景——分析报告

用户输入：
> [写作需求] 撰写一份关于新能源汽车市场现状的分析报告，面向投资人，篇幅约2000字，正式风格。
> [提纲] 1. 市场概况 2. 竞争格局 3. 发展趋势 4. 投资建议
> [参考资料1] [当前工作目录]/ev-report-2025.pdf
> [参考资料2] [当前工作目录]/tesla-q4-2025.pdf

执行流程：
1. 拆解三项输入，确认理解
2. 完整读取两份资料，分析内部逻辑
3. 分析两份资料间的关联（直接引用、互补、矛盾等）
4. 评估提纲合理性，提出优化建议：用户初始提纲编号为「1. 2. 3. 4.」，不符合公文标题规范。在步骤4（对应 `_router/step-04.md`）中将其转换为标准格式：'一、市场概况；二、竞争格局；三、发展趋势；四、投资建议'
5. 识别信息缺口（如最新月度数据缺失），联网搜索并交叉验证
6. 逐章撰写，标注来源，严格遵守文风、语气、标题规范
7. 逐项自检
8. 按模板输出

## 示例2：正常场景——商务合作建议书

用户输入：
> [写作需求] 撰写一份向XX市政府提交的"数字经济产业园项目合作建议书"，目标受众为市发改委和招商局主要领导，篇幅约3000字，需极具说服力。最终输出为 .docx 文件。
> [参考资料1] （项目选址地块资料、公司核心优势与过往案例）
> [参考资料2] （XX市十四五数字经济发展规划摘要）

执行要点：
1. 角色切换为"首席项目策划专家"，以"打动业主、推动项目落地"为核心目标
2. 若用户未提供提纲，自动采用七章"基础项目建议书提纲"
3. 严格遵守"换位思考"原则，将公司技术优势翻译为甲方关心的"产业升级、税收就业、数字化治理"等价值点
4. 在"预期效益"等章节进行量化测算或引用同类项目标杆数据
5. 结尾给出明确的下一步行动建议
6. 构造 shell_exec 命令调用 officecli 完成文件创建与写入（对应步骤9 `_router/step-09.md`）
7. 写入完成后在独立 shell_exec 中执行 QA 校验（对应步骤10 `_router/step-10.md` 的 Delivery Gate）
8. 执行错误检测（4条规则）确认写入成功

## 示例3：缺少提纲场景

用户输入：
> [写作需求] 撰写一份关于"AI在制造业中的应用"的调研报告，面向企业管理层，约1500字，正式风格。
> [参考资料1] [当前工作目录]/ai-manufacturing-2025.pdf

执行要点：
1. 识别到提纲缺失，标记为「提纲缺失」
2. 在步骤4（对应 `_router/step-04.md`）中，根据写作需求（调研报告，面向管理层）和参考资料主题，自动草拟提纲
3. 将草拟的提纲在「提纲调整说明」中公示，说明生成依据
4. 若参考资料仅覆盖了AI在制造业中的应用案例，缺少政策背景和未来展望的数据，则在步骤4（对应 `_router/step-04.md`）中标注第一章和第五章为信息薄弱章节，并在步骤5（对应 `_router/step-05.md`）中安排针对性搜索补全
5. 然后正常执行后续步骤

## 示例4：PDF参考资料场景

用户输入：
> [写作需求] 基于 PDF 报告撰写分析文稿。
> [参考资料1] [当前工作目录]/industry-report-2025.pdf（约 80 页）

执行要点：
1. 识别资料类型为 PDF——不通过 OfficeCLI 分片读取，通过系统原生文件读取能力直接处理
2. 若 PDF 文件大小在上下文限制内，直接完整读取
3. 若 PDF 文件过大超出上下文限制，告知用户："PDF 文件过大，请提供文件摘要或关键章节，或拆分文件后重新上传。"

## 示例5：边界场景——"不需要确认，直接写"

用户输入：
> 根据这些材料帮我写个方案，不需要确认，直接写。
> [参考资料1] ……（仅一份简短材料）

执行要点：
1. 识别到参考资料仅一份且信息基础较薄
2. 在「资料解析说明」中明确指出：「本次仅1份参考资料，信息基础较薄，部分内容需联网补充」
3. 若提纲中某些章节完全无资料支撑且无法通过搜索补足，在「补充信息说明」中声明缺口
4. 因用户明确「不需要确认」，跳过步骤1（对应 `_router/step-01.md`）的确认节点，直接执行完整流程
5. 确保信息缺口对用户透明

## 示例6：超长Office参考资料场景

用户输入：
> [写作需求] 基于以下三份文件撰写分析报告。
> [参考资料1] [当前工作目录]/项目可行性研究.docx（约 150 页）
> [参考资料2] [当前工作目录]/市场调研数据.xlsx
> [参考资料3] [当前工作目录]/项目汇报.pptx（约 150 页）

**docx 文件的分段读取**：

第一步：概览定向 + 持久化映射表
```bash
officecli view "[资料路径]/项目可行性研究.docx" outline
```
解析输出，构建「标题-段落索引-稳定ID映射表」。

第二步：按段落范围分段读取
```bash
officecli view "[资料路径]/项目可行性研究.docx" text --start 1 --end 18 --max-lines 400
```

第三步：精准探查关键节点
```bash
officecli get "[资料路径]/项目可行性研究.docx" "/body/p[@paraId=GGG777]" --depth 2 --json
```

**xlsx 文件的分段读取**：

第一步：概览定向
```bash
officecli view "[资料路径]/市场调研数据.xlsx" outline
```
构建「工作表-区域-命名范围-关键单元格映射表」。

第二步：按区域分段读取（由于 `officecli view text` 在 xlsx 中不支持 `--start/--end`，采用以下替代方式之一）
- 方式一：获取前 N 行（头部样本）
```bash
officecli view "[资料路径]/市场调研数据.xlsx" text --max-lines 200
```
- 方式二：按单元格范围精准提取
```bash
officecli get "[资料路径]/市场调研数据.xlsx" "/汇总/A1:Z50" --json
```
- 方式三（推荐用于超大文件）：导出 CSV 后使用外部工具分片
```bash
officecli view "[资料路径]/市场调研数据.xlsx" csv --sheet 汇总 > data.csv
```
（随后使用 PowerShell 的 `Select-Object -Skip 200 -First 200` 或 Python 等工具分片读取）

第三步：精准探查关键节点
```bash
officecli get "[资料路径]/市场调研数据.xlsx" "/汇总/B5" --json
```

**pptx 文件的分段读取**：

第一步：概览定向
```bash
officecli view "[资料路径]/项目汇报.pptx" outline
```
构建「幻灯片-标题-形状/元素映射表」。

第二步：按幻灯片范围分段读取
```bash
officecli view "[资料路径]/项目汇报.pptx" text --start 3 --end 5 --max-lines 200
```

第三步：精准探查关键节点
```bash
officecli get "[资料路径]/项目汇报.pptx" "/slide[4]/shape[@name=SlideTitle]" --depth 1 --json
```

**关键约束**：
- 禁止一次性拉取全文
- **xlsx 文件不支持 `--start/--end` 分页**，须使用上述替代方式
- 每次读取的数据量应控制在上下文允许范围内（建议不超过 200 行或 2000 个单元格）
