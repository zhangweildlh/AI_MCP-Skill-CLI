# 跨会话断点续跑协议（Session-Resume Protocol）

> 适用场景：LLM 对话会话限额耗尽，需新开会话接力续跑而非从头重跑。
> 配套落地：`_router/bootstrap.md`（RESUME-PROBE 首动作）、`assets/_流水线状态.md`（已确认节点 / 决策日志 / 阶段检查点）、`_router/_contract.md`（续跑维度）、各 `step-NN.md`（步骤内 checkpoint）。
> 设计来源：`跨会话断点续跑对抗设计.md`。单会话首次运行流程**完全不变**（RESUME 为叠加分支）。

---

## 0. 核心原则

1. **状态文件为唯一权威真相源**：所有续跑决策以 `[输出目录]/_流水线状态.md` 为准，不以对话上下文为准。
2. **续跑优先于新建**：新会话检测到既有状态文件存在，必须进入 RESUME 模式读回继承，**禁止无条件重建覆盖**。
3. **能力刷新不覆盖业务状态**：新会话重探工具能力（尤其 Firecrawl 形态：直连或中继经 Dynamic-mcp，以状态文件「工具能力映射表」为准）仅刷新"能力字段"，不动全局参数 / 前序产出清单 / 决策日志。
4. **精确断点定位**：凭「阶段检查点」定位到步骤内子阶段（关键词级 / 分片级），仅补做缺失 / 半成品部分。

---

## 1. RESUME-PROBE（会话首动作，强制）

每个新会话在 `_router/bootstrap.md` 最前执行，取代"无条件 Gate-0 全量新建"：

```
FILE_STAT([输出目录]/_流水线状态.md)
├─ 不存在 → NEW-BUILD 路径（原 Gate-0 全量新建，逻辑不变）
└─ 存在   → RESUME 路径（进入 §2 → §3 → §4）
```

- 探测仅做 `FILE_STAT`，**不读内容、不写内容**，避免误改。
- 若探测本身失败（如目录无权限），报告用户并暂停，不得臆造状态文件。

---

## 2. RESUME-CHECK（产出物完整性三清单）

进入 RESUME 后，先读状态文件与「前序产出清单」，对每个已记录产出物做存在性 + 完整性校验（**完整性判定须按 `references/16-self-check-A/B/C/D.md` 标准档必过项**，非模糊"最小完整性"），生成三清单：

| 清单 | 含义 | 处理 |
|------|------|------|
| **已完成（done）** | 文件存在且校验通过 | 直接继承，不重做 |
| **半成品（half）** | 文件存在但阶段检查点显示仅写到子阶段 | 仅补做剩余子阶段 |
| **缺失（missing）** | 文件不存在 / 校验失败 | 从对应步骤重做 |

**校验对象**（按状态文件「当前步骤」向后推断）：
- 步骤1/2/3 产出：`_card_*.json`、`_交叉引用结果.json`、全局参数。
- 步骤4 产出：`_提纲.md`；结合「阶段检查点」判断处于 `4.6-提纲待确认` 还是 `4.7-提纲已落盘`。
- 步骤5 产出：`_网络搜索素材.md`；结合「阶段检查点」的 `Kx-AnySearch done` / `Kx-Firecrawl done` 判断各关键词双引擎完成度。
- 步骤9 产出：`_最终文稿.*`；结合「阶段检查点」的 `N/M 片` 判断分片完成度。

**硬完成标志**：对「已完成」清单中标记 ✅ 的步骤（✅ 来源 = 状态文件 §14「逐步自检登记」中该步的 ✅通过 登记），新会话**不得**再次执行其分析逻辑，仅引用其产出。

> **边界（C3）**：续跑场景一律走本 RESUME-CHECK（含标准档必过项全量回读），**不**触发设计点 4 第③级"轻检"；二者不重叠——续跑已含全量读，无需再轻检。

---

## 3. RESUME-LOAD（全量回读契约）

按固定顺序全量读回前序产出物，重建上下文（不依赖聊天记忆）：

1. 读 `[输出目录]/_流水线状态.md` 全文（含全局参数、工具能力映射表、已确认节点、决策日志、阶段检查点）。
2. 读「前序产出清单」列出的每个文件（按步骤顺序）：
   - `_card_[资料ID].json` → `_交叉引用结果.json` → `_提纲.md` → `_网络搜索素材.md` → `_正文过程稿.md` → `_相似段落标记.md` → `_最终文稿.*`。
3. 读 `references/13-anysearch-integration.md`、`references/14-firecrawl-guide.md`（续跑仍需双引擎能力参考）。
4. 读 `references/15-resume-protocol.md`（本文件，确认续跑规则）。

> 回读后输出 RESUME-BRIEF（见 §5），再据三清单（§2）决定续跑起点。

---

## 4. 能力刷新不覆盖 + 路由对齐（关键）

### 4.1 能力刷新不覆盖
- 新会话**必须**重新探测工具能力（环境可能变化，尤其 Firecrawl 索引）。
- 重探结果**仅写入**状态文件「工具能力映射表」「双引擎搜索能力状态」等**能力字段**。
- **严禁**用新探测覆盖：全局参数、前序产出清单、已确认节点、决策日志、阶段检查点。
- 若探测到能力与原记录**不一致**（如某引擎由可用变不可用），须：
  - 在「决策日志」追加记录该变化（含时间戳）；
  - 据新能力调整续跑策略（如原双引擎现仅剩 NATIVE_WEB → 步骤5 降级单轨，但**已完成的双引擎素材保留**，不重做）。

### 4.2 路由对齐（形态由映射表决定）
- Firecrawl 能力探测与调用**依首会话已写入状态文件「工具能力映射表」的形态**（直连或中继经 Dynamic-mcp），续跑与首会话完全一致，不得变更形态：
  - 直连形态：直接复用 `firecrawl_*` 工具（或平台前缀 `mcp__firecrawl__*`），无索引驱逐问题。
  - 中继形态：先 `mcp__Dynamic-mcp__get_dynamic_tools(group="firecrawl-mcp")` 定位组名（以 `list_groups` 实际返回为准），若 `call_dynamic_tool` 不在索引则 `ToolSearch` 重索引（连接器重连会丢索引，实测）。
- 续跑会话的 Firecrawl 调用与首会话**完全一致**：直连则 `firecrawl_<能力>(args={...})`；中继则 `mcp__Dynamic-mcp__call_dynamic_tool(group="<实际组名>", name="firecrawl_*", args={...})`。
- AnySearch 为固定外部命令（硬编码），不受会话限制，直接复用状态文件登记的命令；若 `runtime.conf` 与主文件镜像不一致（不应发生），以 `runtime.conf` 为准并修正镜像。

---

## 5. RESUME-BRIEF（引导语模板）

续跑上下文重建后，向用户输出（自然语言，中文）：

```
【续跑恢复】检测到既有状态文件，已自动进入续跑模式（未覆盖前序进度）。
- 当前进度：步骤N / 共10步（阶段检查点：<如 K3-Firecrawl done / 2/5 片>）
- 已完成：<done 清单要点>
- 待续跑：<half + missing 清单要点>
- 能力刷新：双引擎状态 = <AnySearch 可用 / Firecrawl 可用 / NATIVE_WEB 补偿 ...>（仅刷新能力字段，未动业务状态）
- 下一步：<从步骤N 子阶段X 继续 / 补做缺失产出>
```

- 若检测到「已确认节点·步骤1/4=是/跳过」，明确告知"确认节点已继承，不再重复打扰"。
- 若「决策日志」有用户历史微调，列要点提示继承（如"已继承您对第三章的压缩要求"）。

---

## 6. 验证方法（证明续跑可用）

按本文件 §2 的「产出物完整性三清单」+ `references/16-self-check-A/B/C/D.md` 标准档必过项，构造以下断点场景逐项核对各步骤文件是否正确落地：

### 场景 A：步骤4 中途断点
1. 首会话运行至 4.6 确认等待用户，人为停止（状态文件「阶段检查点」=`4.6-提纲待确认`，「已确认节点·步骤4」未写）。
2. 新会话触发技能 → RESUME-PROBE 命中 → RESUME-CHECK 判 `_提纲.md` 缺失 / 待确认。
3. 校验：状态文件未被覆盖；前序步骤1–3 产出未被重做；双引擎能力重探成功（Firecrawl 形态按状态文件映射表生效：直连或中继）；新会话从 4.6 待确认子阶段继续，不再走步骤1。

### 场景 B：步骤5 关键词级断点
1. 首会话完成 K1–K2 双引擎、K3 仅 AnySearch（状态文件「阶段检查点」=`K1-AnySearch done`/`K1-Firecrawl done`/`K2-*`/`K3-AnySearch done`，缺 `K3-Firecrawl done`），人为停止。
2. 新会话 → RESUME → RESUME-CHECK 判 K3 为 half（仅 AnySearch）。
3. 校验：仅补跑 K3 的 Firecrawl 轨道，K1/K2 不重做；`_网络搜索素材.md` 仅追加 K3-Firecrawl 结果。

### 场景 C：步骤9 分片级断点
1. 首会话完成 2/5 片（状态文件「阶段检查点」=`2/5 片`）。
2. 新会话 → RESUME → 从第 3 片续写，不重做前 2 片。

### 回归判据
- 状态文件在建 RESUME 前、后**内容一致**（除能力字段刷新与新增 checkpoint）。
- 前序产出物文件**未被重建、未被覆盖**（时间戳 / 大小不变或仅追加）。
- 双引擎在新环境重探**均成功**，Firecrawl 形态按状态文件映射表（直连或中继）生效。
- 续跑会话**未**重复已确认节点（步骤1/4 确认节点被跳过）。
