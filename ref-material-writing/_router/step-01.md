## [执行]

### 1.1 识别并结构化 12 维度信息
从用户输入提取以下 12 维度，任一缺失 / 模糊 / 矛盾则转入 1.2 访谈：

| 维度 | 说明 |
|------|------|
| 1. 写作主题 | 全文核心论点，须为明确主张句 |
| 2. 写作目的 | 期望达成的效果 |
| 3. 写作思路 | 宏观逻辑框架与论证脉络 |
| 4. 受众 | 预期阅读 / 评审者 |
| 5. 写作文体 | 文件体裁（调研报告 / 建议书 / 方案等）|
| 6. 总字数 | 最终文稿总字数（汉字）|
| 7. 初始提纲 | 一级 / 二级章节标题（可缺，步骤4 草拟）|
| 8. 参考资料 | 所有外部材料（路径 / URL + 用途）|
| 9. 最终文稿文件格式 | `.docx`（默认）或 `.md` |
| 10. 当前工作目录 | 读取参考资料基准路径 |
| 11. 输出目录 | 输出文件保存路径 |
| 12. 其他需求与约束 | 特殊要求（如禁第一人称）|

### 1.2 结构化访谈（信息补全）
- 每轮≤3 个问题，聚焦缺失维度，开放式提问。
- 矛盾信息指出矛盾点并要求澄清；循环直至所有维度明确赋值。

### 1.3 确认节点（闭环校验）
- 将 12 维度整理为结构化清单呈现用户。
- 用户可选："确认无误"→ 进入步骤2；"调整/修改"→ 循环；"无需确认，直接写"→ 进入步骤2。
- **未获明确确认前不得擅自进入步骤2。**
- **确认结果持久化（跨会话续跑）**：
  - 用户"确认无误"或"无需确认，直接写"→ 立即向状态文件「已确认节点」写 `步骤1确认：是(ts)` 或 `步骤1确认：跳过(ts)`；"调整/修改"循环后最终确认，同样写 `是(ts)`。
  - 用户对 12 维度的微调、特殊约束（如禁第一人称、指定格式）即时写入状态文件「决策日志」（含时间戳），避免仅存于聊天上下文。
  - 续跑会话若检测到「已确认节点·步骤1=是/跳过」，则跳过本步确认节点，直接沿用状态文件全局参数。

### 1.4 异常处理
| 场景 | 处理 |
|------|------|
| 拒绝提供某维度 | 暂停，告知该维度为必要前提 |
| 信息矛盾 | 指出矛盾点，请用户明确优先级 / 修正 |
| 路径不存在 / 无权限 | 请用户确认路径 |
| 多维度长期缺失且回避 | 标"未提供"，请用户确认是否允许 AI 填充 |

### 1.5 进入步骤2 的前置条件
- 通过 1.3 确认节点；所有 12 维度已填写完整，无未解决矛盾。
