# jasminK11/claude-5-why-skill 模块方法论缓存

**模块用途**：Phase 3 深度分析增强——提供结构化的 5Why 根因追问机制  
**激活条件**：Phase 3 信息充足后  
**接口契约**：
- 输入：`{ "待验证假设": [str], "placeholders": { ... } }`
- 输出：`{ "5why链": [{"阶段":int,"问题":str,"回答":str,"置信度":str}], "what_for": str|null, "终止原因": "根因达到"/"死胡同回退"/"复杂系统标注" }`

## 核心方法论

### 1. 丰田 5Why 方法（标准版）

**核心原则**：
- 5 是指导数，非铁律；2-3 次可停，抵达根因即止
- 每次只问一个 why，对话式逐步深挖
- 死胡同时回退 1-2 层，改问其他角度
- 适合线性因果（技术/流程/缺陷）；复杂社会系统需标注为假设

**执行步骤**：
1. **捕获观察**：必须是具体可验证的事实，非解读/推测
2. **逐级追问**：
   - 1st why：为什么会发生 [观察]？
   - 2nd why：为什么会发生 [1st 的回答]？
   - ...
   - 最多 5 次，或提前终止
3. **命名根因**：给出明确的根因陈述，而非症状描述
4. **推导解决方案**：治本非治标，方案必须针对根因

### 2. what-for 变体（目标导向反推）

**适用场景**：OKR 目标开发、战略决策、需求澄清
**方法**：将「为什么」替换为「为了什么」
- 例：「我们要实现 X」→「为了什么要实现 X？」→「为了 Y」→「为了什么要实现 Y？」...
- 最终抵达核心价值或战略意图

### 3. 规则与约束

| 规则 | 说明 |
|------|------|
| 最大追问次数 | 5 次 |
| 最小追问次数 | 2 次（若 2 次已达根因可停） |
| 死胡同处理 | 回退 1-2 层，改问其他角度 |
| 复杂系统标注 | 涉及人/组织/文化等多因果时，标注「待验证假设」 |
| 置信度评估 | 高：追问链完整且有证据支撑 / 中：链基本完整但有假设 / 低：链断裂或纯推测 |

### 4. 输出模板示例

```markdown
## 5Why 追问链

### 假设：[待验证的假设描述]

1st why：为什么会 [现象]？
→ 回答：[直接原因]

2nd why：为什么会 [直接原因]？
→ 回答：[更深层原因]

3rd why：为什么会 [更深层原因]？
→ 回答：[根因候选]

4th why：为什么会 [根因候选]？
→ 回答：[确认的根因]

5th why：为什么会 [确认的根因]？
→ 回答：[不可再分的根本原因]

### 终止原因
根因达到 / 死胡同回退 / 复杂系统标注

### what-for 变体（如适用）
为了什么要 [目标]？
→ 为了 [更高层目标]
→ 为了 [核心价值/战略意图]

### 结论
- 根因：[明确陈述]
- 置信度：[高/中/低]
- 未解决的假设：[列表]
```

### 5. 降级方案（模块不可用时）

退化至多维度脑暴雨式分析：
- 从技术/流程/风险/成本/人员/时间等维度穷举可能原因
- 使用鱼骨图思维（人机料法环）进行结构化分析
- 输出：可能原因列表 + 置信度评估 + 需验证的关键假设
