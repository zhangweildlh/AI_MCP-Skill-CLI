# sequential-thinking 适配层（思维审计基础设施）

> 本文件为 deep-discuss 自有适配层，非外部 git 上游模块，故**不采用 commit 版本锁定**，按「运行时探测」机制管理（详见 §3 探测协议）。本文件不写入 `version-lock.md` 的锁定表。

## 1. 定位与价值

本适配层将「分步推理 / 思维记录」类 MCP 服务（以下简称「思维审计服务」）作为 deep-discuss 的**跨阶段基础设施层**，而非单一阶段增强模块。它弥补 deep-discuss 原有的三个结构性缺口：

1. **隐性推理不可审计**：原 7 阶段的核心推理发生在模型内部，无显式留痕，用户无法回看「为什么走到这个结论」。
2. **无分支探索**：原流程线性推进，无法优雅地「先分叉尝试另一条路、再决定哪条更好」。
3. **无跨会话持久化**：一次讨论的思维链路随对话结束而丢失，无法在后续会话导入续推。

> ⚠️ **约束**：本文件中的所有服务名、工具名、路径均作为**示例**出现（如 `sequential-thinking`、`process_thought`、`dynamic-mcp`、`dmcp-mcp`）。实际激活时一律以**运行时探测**到的真实名称为准；本文件与 SKILL.md 均**不硬编码**任何具体服务名、工具名或路径。需要引用时以「例如」措辞，并明确「以探测结果为准」。

## 2. 能力特征契约（探测匹配依据，不依赖具体名称）

是否采用某 MCP 服务作为思维审计层，取决于它是否具备以下**能力特征集合**。探测时按「能力特征」匹配，而非按名字匹配——这样即使服务改名、改路径、增减工具，只要能力特征仍在，即可自动适配。

| 能力特征 | 期望行为 | 在 deep-discuss 中的用途 |
|---|---|---|
| 记录单条思维（带阶段标签 / 序号 / 可分支 / 可修订） | 输入结构化思维片段，返回结构分析 | Phase 1-7 各阶段关键判断留痕 |
| 生成结构化摘要 | 汇总已记录思维，输出各阶段摘录 + 统计 | Phase 收尾向用户汇报的素材 |
| 清空历史 | 不可逆删除当前会话思维 | 切换新问题前重置 |
| 导出会话 | 保存到本地文件（限定目录） | 跨会话持久化（可选增强） |
| 导入会话 | 从文件载入（替换当前） | 续推历史讨论（可选增强） |

只要一个 MCP 分组 / 服务同时提供「记录 + 摘要 + 清空」三件套，即视为可适配；「导出 / 导入」为可选增强（用于持久化），缺失不阻断适配。

## 3. 探测协议（加载时必做，本次会话仅一次）

### 3.1 何时探测
- 每次**激活** deep-discuss 时（进入 Phase 1 之前）执行一次；**当前对话会话内只探测一次**，后续激活复用本次结论（无论跨多少个用户轮次，同一会话不重复探测）。
- 探测位于「加载时启动自检」之前或紧邻，结果写入会话级缓存变量（例如 `SEQ_THINK_PROBE`）。

### 3.2 怎么探测（能力特征匹配，非名称匹配）
1. **发现当前主机「全部可用 MCP 工具 / 服务」——枚举机制本身必须由运行时主机决定，禁止假设或硬编码任何具体 API**。例如 `list_groups` / `get_dynamic_tools` 仅是「某聚合器」的示例，不代表唯一或默认机制；不同主机 / 不同聚合器的发现 API 名称各异，须运行时从主机实际能力中发现，不得写死。一个服务可能以下列**任意一种拓扑**出现，探测须对三类一视同仁、不得偏废：
   - **直接连接**：服务直接连到主机，工具以 `mcp__<服务名>__<工具名>` 等形式直接暴露（不经任何聚合器）；
   - **经聚合器中转**：服务作为某聚合器的一个「分组」暴露，聚合器名称任意（示例：`dynamic-mcp`、`dmcp-mcp` 或用户自定义名），**不得假设为某特定名称**；
   - 探测应同时覆盖「主机直接暴露的工具」与「各聚合器分组内的工具」，不得只扫聚合器分组而漏掉直连服务。
2. 对每个被发现的服务 / 工具集（无论直连还是分组内）读取其工具清单，比对 §2 能力特征：
   - 若存在「记录单条思维 + 生成摘要 + 清空历史」三件套 → 登记为思维审计层，记录：
     - `available = true`
     - `access_path`：上述三类拓扑之一（直接连接 / 经某聚合器中转）——以探测到的真实接入途径为准，聚合器名称任意，不限定为 `dynamic-mcp`；
     - `tool_names`：探测到的真实调用名（含可选的导出 / 导入工具）；
     - `functions`：各工具一句话功能；
3. 若遍历完无任何服务 / 工具集匹配 → `available = false`，记录原因（如「未发现有具备思维记录能力的 MCP 服务」）。

### 3.3 探测结果缓存与复用
- 探测结果缓存在会话级变量，整个会话内所有 Phase 复用同一结论。
- 会话内二次激活 deep-discuss（如用户切换到新问题）**不重新探测**，直接读取缓存。
- 仅在以下情况需重新探测：新开对话会话，或显式收到「重新探测」指令。

### 3.4 失败 / 不可用处置
- `available = false` 时：**静默降级**，不打扰用户、不阻塞流程，后续所有阶段按「基础模式」运行（即当前 deep-discuss 原有行为，思维审计层完全不参与）。
- 若探测过程中接入途径异常（如聚合器未运行），按「不可用」处理；默认静默，可选在 Phase 1 开头以一行提示告知用户：`[思维审计层不可用，已切换至基础模式]`。

### 3.5 强制探活执行协议（激活必做、不可仅文档检查）

> ⚠️ **本节为 P3-03 错判的根因修复**：此前仅依据「适配层文档存在」「SKILL.md 提及该层」即判定服务可用，未真实调用，导致把"文档存在"误当"服务可用"。本节约强制每次激活 Skill 时**真实执行一次探测调用**，以运行时结果为准。

**强制动作（激活后、Phase 1 之前、不可省略）**：

1. **枚举工具**：调用 `call_dynamic_tool`，`group='sequential-thinking'`，`name='get_dynamic_tools'`，列出该分组暴露的全部工具。预期返回含 `process_thought` / `generate_summary` / `clear_history` 等。
2. **实测调用**：调用 `call_dynamic_tool`，`group='sequential-thinking'`，`name='process_thought'`，`args={ "thought": "<探测探针：deep-discuss 激活自检>", "stage": "探测", "total_thoughts": 1, "next_thought_needed": false }`。**必须以此次真实返回判定可用性**。
3. **判定结论**：
   - 返回 `isError: false` 且含结构化分析（阶段进度 / 主线程位置 / 时间戳任一项）→ **`available = true`**，登记 `access_path='经 dynamic-mcp 聚合器中转'`、`tool_names` 为真实返回名、`functions` 为各工具一句话功能；结果写入会话级缓存变量（例如 `SEQ_THINK_PROBE`），会话内复用。
   - 返回 `isError: true`、调用超时、或聚合器未连接 → **`available = false`**，按 §3.4 静默降级；**不得因文档存在而覆盖此结论**。
4. **清理探针**：若实测调用成功，调用 `call_dynamic_tool`，`group='sequential-thinking'`，`name='clear_history'` 清理本次探针思维，保持服务状态干净（可选，但推荐）。
5. **激活探活器**：运行技能根目录 `scripts/probe_seq_thinking.py` 获取上述步骤的清单化提醒与验收点（该脚本不参与 MCP 调用，仅作激活时的 checklist 引导）。

**调用约定（实测验证有效）**：
- 必填字段为 `group` + `name`（**不是** `tool`）；
- 工具参数包在 `args` 字段（**不是** `arguments`）；
- `group` 取值受枚举约束：`sequential-thinking` / `codebase-memory-mcp` / `TickTick` / `firecrawl-mcp` / `filesystem` / `Everything-search`。

## 4. 各阶段集成点（仅在 available=true 时生效）

> 下表以**示例**工具名 `process_thought` / `generate_summary` / `clear_history` / `export_session` / `import_session` 说明映射；实际调用名以探测结果 `tool_names` 为准，不得据此硬编码。

| 阶段 | 思维审计层用法 | 降级（不可用） |
|---|---|---|
| Phase 1 接收信息 | 用「记录单条思维」工具写入「信息摘要」思维（示例 stage=问题定义），锚定上下文 | 仅模型内复述，无显式记录 |
| Phase 2 问题审查 | 三层审查每条关键判断各记一条思维；对「替代问题成立性」用分支（`branch_from_thought`）探索 | 原有三层审查，无分支 |
| Phase 3 深度分析 | 5Why 每一步记一条思维；遇死胡同用分支探索其他角度；用修订（`is_revision`）修正早前结论 | 原有脑暴雨式分析 |
| Phase 4 方案设计 | 每个候选方案记一条思维并打标签（如方案 A / B），便于回溯对比 | 直接给方案列表 |
| Phase 5 方案自检 | 每个失败模式记一条思维，标注被挑战假设 / 公理 | 原有检查清单 |
| Phase 6 最终确认 | 用「生成摘要」工具产出结构化思维链路，作为向用户汇报的素材 | 直接输出确认报告 |
| Phase 7 执行（可选） | 每完成关键步骤记一条思维；执行前用「清空历史」或「导出会话」保存上下文 | 逐步汇报，无留痕 |
| 会话切换 / 结束 | 用「导出会话」保存；新问题开始前「清空历史」（或「导入会话」续推旧讨论） | 无持久化 |

## 5. 接口契约（最小调用约定）

本层**不定义强制 JSON schema**（由被探测服务的真实接口决定）。主干仅约定最小调用约定，具体字段名以探测到的真实接口为准：

- **记录思维**最小输入（示例字段）：`{ "thought": "<文本>", "stage": "<阶段标签>", "total_thoughts": <int>, "next_thought_needed": <bool>, "tags": [可选], "branch_from_thought": <可选int>, "is_revision": <可选bool> }`
- **生成摘要**输出：由服务确定性返回，主干原样呈现或择要融入阶段输出，不二次加工。
- **清空 / 导出 / 导入**：按服务真实参数调用，主干不二次加工。

## 6. 维护提示
- 本适配层**不绑定任何具体服务版本**：若上游服务改名、改路径、或新增 / 移除工具，只需在运行时探测中重新匹配能力特征，无需改动本文件（除非能力特征集合本身需升级）。
- 本文件不进入 `version-lock.md` 的 commit 锁定表（非 git 上游模块）；其完整性由 `scripts/selfcheck.py` 的第 3 项检查覆盖（存在性 + 探测协议标记），缺失时不致命（SKIP）。
- 若需将某特定服务「钉固」为首选（如性能 / 稳定性考虑），在 SKILL.md 探测节中以「示例偏好」形式说明，而非硬编码强制。
