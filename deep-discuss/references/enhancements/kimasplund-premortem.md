# kimasplund/premortem-skill 模块方法论缓存

**模块用途**：Phase 5 方案自检增强、Phase 6 最终确认增强——提供极详尽的事前验尸机制  
**激活条件**：问题复杂度 ≥ 高（或用户指定）  
**接口契约（Phase 5）**：
- 输入：`{ "方案列表": [{"名称":str,"描述":str,"前提": [str]}], "placeholders": { ... } }`
- 输出：`{ "修订方案": { ... }, "tripwires": [str], "decision_rule": {"触发条件": str, "行动": str}, "报告段落": ["autopsy","verdict","rebuild","adversary","tripwires"] }`

**接口契约（Phase 6）**：
- 输入：Phase 5 输出的修订方案
- 输出：`{ "calibration_review": { ... }, "commitment_level": "champion/endorse/accept/comply", "decision_rule_final": str, "具体承诺": str }`

## 核心方法论（Premortem-Evolved）

### 1. Proportionality Screen（比例性筛选）

**目的**：避免对低风险问题过度仪式化，节省认知资源  
**执行**：
1. 对每个方案评估风险等级：可能性（L）× 影响（I）矩阵
2. 等级划分：
   - 低风险：L≤2 且 I≤2 → **直接跳过完整 premortem**，进入 Phase 6
   - 中风险：其他组合 → 执行简化版 premortem（仅 Autopsy + Verdict + Tripwires）
   - 高风险：L≥4 或 I≥4 → 执行完整五段报告 + Decision Rule
3. 记录筛选结果和理由

### 2. Steelman First（钢人先行）

**核心原则**：先写计划的最强支持案，再进行攻击  
**执行**：
1. 对每个方案，先列出所有支持理由（数据、逻辑、先例、专家意见）
2. 强迫自己把支持案写到最强（Steelman Pro）
3. **然后**再从对立面攻击（寻找失败模式）
4. 避免 Strawman（稻草人）谬误，确保攻击的是真正的最强版本

### 3. 失败模式生成与削减

**生成**：
- 针对每个方案，生成 12-15 个候选失败模式
- 每个模式必须包含：failure-class 分类（技术/执行/市场/外部/组织/资源/人员/假设）
- 使用多视角：技术视角、业务视角、用户视角、运维视角、黑客视角

**削减**：
- 按 failure-class 分组，每组保留最具代表性的 1-2 个
- 最终削减至 ~7 个核心失败模式
- 标记每个模式的：事件链、隐藏假设、早期信号、概率伤害估算

### 4. 五段报告结构

#### Autopsy（尸检——逆向解剖每个失败模式）
```
失败模式 X：
- 事件链：[步骤1 → 步骤2 → 步骤3 → 失败]
- 隐藏假设：[假设A、假设B...]
- 早期信号：[指标X异常、用户投诉增加、依赖方延期...]
- 概率伤害：L=[1-5] I=[1-5] 预估损失=[具体描述]
```

#### Verdict（裁决——战略综合分析）
- 最可能失败的模式：[名称 + 理由]
- 最危险的失败模式：[名称 + 理由]
- 关键隐藏假设：[列表]
- 不受控依赖：[外部依赖列表]

#### Rebuild（重建——修订计划）
基于 Verdict 调整方案：
- 针对最可能/最危险失败模式的缓解措施
- 针对关键隐藏假设的验证计划
- 针对不受控依赖的应急预案
- 产出：修订后的完整方案

#### Adversary（对手——对抗性审查）
- 从竞争对手/批评者/黑客视角重新审视修订后方案
- 提出至少 3 个新的攻击角度
- 评估修订措施是否真正有效

#### Tripwires（绊线——发布清单）
- ≤8 项可验证的早期信号（每项含：指标、阈值、检查频率、责任人）
- 例：「部署后第1周日均错误率 > 1% → 触发回滚」
- 必须具体、可测量、有时限

### 5. Decision Rule（决策规则——IF/THEN 门控）

**标准阈值**：
```
IF 失败模式概率 > 40% → 暂停，重新设计
IF 失败模式概率 20-40% → 修订方案并增加缓解措施，再次评估
IF 失败模式概率 < 20% → 进入 Phase 6
```

**校准概率份额（粗梯）**：
~5% / ~10% / ~15% / ~20% / ~30% / ~40%
（避免虚假精确，使用粗粒度概率）

### 6. Phase 6 增强：Calibration Review & Commitment

#### Calibration Review（校准审查）
- 重新校准所有失败模式的概率份额
- 检查是否存在过度自信或过度悲观
- 使用外部基准率进行参照（如行业平均失败率）

#### Commitment 等级（承诺等级）
| 等级 | 含义 | 适用场景 |
|------|------|----------|
| Champion | 全力推动，投入个人信誉 | 核心战略项目 |
| Endorse | 公开支持，提供资源 | 重要但非核心项目 |
| Accept | 接受执行，不主动阻碍 | 常规项目 |
| Comply | 被动配合，保留异议 | 强制合规项目 |

#### 具体承诺索取
- 要求用户给出**一项**具体、可验证、有时限的行动承诺
- 格式：「我将在 [日期] 前完成 [具体动作]」
- 记录在最终确认报告中

## 降级方案（模块不可用时）

退化至原有 Phase 5 检查清单（5项）：
- 是否有遗漏的场景或边界条件？
- 方案的前提假设是否都成立？
- 实施复杂度是否被低估了？
- 有没有更简单的替代方案被忽略了？
- 方案是否真的解决了 Phase 2 中识别出的所有问题？

Phase 6 退化至原有四项检查（完整性/风险预案/验证方式/补充建议）
