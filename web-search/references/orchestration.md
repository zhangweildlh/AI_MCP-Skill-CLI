# 双引擎编排与多来源印证（web-search 内联，独立可用）

本文件定义 web-search 的多工具、多轨制搜索编排逻辑，为技能自包含内容，运行时不读取、不加载任何外部技能或素材目录文件。

## 总体模型

- 双引擎平权双轨、互不替代、结果合并：AnySearch（引擎 A）+ Firecrawl（引擎 B）。此处「平权」指两轨都必须跑、权重相等，不指时间并行。
- 执行顺序：先跑完 AnySearch（全部关键词），再跑 Firecrawl（全部关键词）；两引擎结果独立、互不影响、最后合并。
- 每关键词两轨都不得留空（强制）。
- LLM 原生 `web_search` / `web_fetch`（NATIVE_WEB）为双引擎任一不可用时的补偿通道，保双轨并行；二者皆不可用则单轨原生（标「[单轨原生搜索]」）。
- 信息缺口阈值：每关键论点 ≥ 2 独立来源；低于阈值触发补充搜索。

## 搜索要素 → 关键词矩阵

- 每个显式/隐藏/衍生关键词均须分别经过 AnySearch 与 Firecrawl 两条轨道，两轨都不得留空。
- 为每个关键词编号为 K1、K2、……，用于来源标签与 checkpoint。

## 缺口识别（5 类）

| 缺口类型 | 判定标准 |
|----------|----------|
| 政策缺少 | 相关主题未引用任何政策文件 |
| 事实缺失 | 关键事件 / 时间节点 / 案例无记载 |
| 数据不全 | 应量化指标无具体数值或仅一份来源 |
| 论据不足 | 佐证关系数 < 2 条 |
| 概念定义不明确 | 专业术语无明确定义 |

## 垂直领域判定（仅 AnySearch 轨道，由你自主决策）

- 依据：用户需求、隐藏诉求、关键词与要素树。
- 执行（一次性、会话内缓存）：对每个判定领域调用一次
  `... anysearch_cli.py get_sub_domains --domains 领域1,领域2,...`
  解析子域及其必填参数，会话内缓存，不重复调用。
- 后续搜索优先选用匹配垂直子域；纯百科类走通用搜索（omit `--domain`）。
- 中文政策/国标特别规则：不走垂直域，直接 `search "关键词" --max_results 10`（omit `--domain`）。详见 `anysearch.md`。

## 轨道 A — AnySearch（先跑完）

对每个关键词执行 2 轮（不足可再 1 轮，最多 3 轮）：

1. 通用 / 垂直搜索：`search` / 垂直 `search --domain X --sub_domain Y` / `batch_search` 并行多关键词。
2. 正文抓取：对高价值 URL 调 `extract "https://..."`（HTML→Markdown，截断 50k）。
3. 结果以标签 `[搜索K{序号}-AnySearch]` 暂存。

## 轨道 B — Firecrawl（AnySearch 全部轮次完成后再跑）

对每个关键词执行 2 轮（最多 3 轮）：

1. 首选 AGENT_SEARCH（`firecrawl_agent`）异步多站研究（中继形态：先 `ToolSearch` 重索引 → 提交；直连形态：直接提交）：提交返回 `task_id` → 下一回合（中继形态需先重索引）调 `firecrawl_agent_status(id)` 回读 → 完成/降级。
2. 降级 fb（agent 超时/失败）：`firecrawl_search`（取前 10→按权重取前 5）+ `firecrawl_scrape` 抓正文。来源权重：政府官网(.gov.cn) > 学术文献 > 权威媒体 > 行业协会 > 大型咨询公司 > 其他。
3. 结果以标签 `[搜索K{序号}-Firecrawl]` 暂存。

顺序与独立性：先完整跑完轨道 A，再启动轨道 B；两轨道结果不互相影响、不互相依赖，最终统一合并入素材文件。

## 双引擎降级 / 补偿（保双轨）

| 能力状态 | 轨道组合 | 顺序 |
|----------|----------|------|
| 双可用 | 轨道 A=AnySearch，轨道 B=Firecrawl | 先 AnySearch 后 Firecrawl |
| AnySearch 不可用 | 轨道 A=Firecrawl，轨道 B=NATIVE_WEB | 先 Firecrawl 后 NATIVE_WEB |
| Firecrawl 不可用 | 轨道 A=AnySearch，轨道 B=NATIVE_WEB | 先 AnySearch 后 NATIVE_WEB |
| 双不可用 | 仅 NATIVE_WEB 单轨 | 标「[单轨原生搜索]」 |

不静默跳过：任一引擎不可用须转入另一轨道或原生通道，并明确记录。

## 单工具三级接力协议（保缺口不漏）

处理「引擎可用但某具体工具本次调用不稳/失败」：

1. 一级接力（跨引擎同功能）：AnySearch 某功能工具不稳/失败 → 改调 Firecrawl 同功能工具（`extract`↔`firecrawl_scrape`/`firecrawl_agent`、`search`↔`firecrawl_search`）；反之同理。
2. 二级接力（LLM 原生同功能）：AnySearch 与 Firecrawl 的该功能工具都不稳/失败 → 改调 LLM 自带同功能工具（`web_search` / `web_fetch`）。
3. 三级跳过（记录 + 末报）：若 LLM 无此同功能工具或原生工具也不稳/失败 → 跳过该具体工作（不得卡死、不得编造），记入交付说明（如「⚠️ 缺口[X]的[抽取]因 AnySearch+Firecrawl+LLM 均失败，已跳过」），并在素材条目标「[数据待核实]」注明原因；任务全部完成后以自然语言向用户详细报告所有被跳过的缺口及原因。

功能 → 工具映射表（接力对齐依据）：

| 功能 | AnySearch | Firecrawl（中继或直接，由 LLM 按环境判定） | LLM 原生（NATIVE_WEB） |
|------|-----------|------------------------------|--------------------------|
| 关键词/网页搜索 | `search` / `batch_search` | `firecrawl_search` | `web_search` |
| 网页正文抓取/抽取 | `extract` | `firecrawl_scrape` / `firecrawl_agent` | `web_fetch` |
| 多站深度研究 | 退化为多次 `search` + `extract` | `firecrawl_agent` | 多次 `web_search`+`web_fetch` 迭代 |

判定「不稳/失败」：超时、返回空壳/报错（如 `Error:`、agent `failed/expired`、extract 4xx/5xx、返回内容与请求无关）、或连续 2 次重试仍异常。不得留空：经三级接力后，结果要么来自某一轨，要么明确「已跳过并记入交付说明 + 末报」。

## 多来源印证与采信标记

- ✅ 双引擎互证（最高级）：同一事实/数据同时被 AnySearch 与 Firecrawl（或任一引擎与原生补偿）命中且一致。
- ✅ 多源验证通过：≥ 2 个独立来源相互印证。
- ⚠️ 单源权威：唯一官方一级政府官网信息单源采用。
- ❌ 未通过：无法印证，标「[数据待核实]」并注明原因。

## 素材记录统一 schema

将验证通过的信息按关键词排列，追加写入 `[输出目录]/[主题]_搜索素材.md`。对话报告与落盘文件均使用以下字段：

```
[搜索K{序号}-AnySearch|Firecrawl|Native]
- 标题：[检索结果标题]
- URL：[来源链接]
- 全文内容：[完整正文或关键段落全文，≥ 300 字；非仅摘要/片段]
- 关联要素：[对应关键词/垂直域]
- 采信标记：✅双引擎互证 | ✅多源验证通过 | ⚠️单源权威 | ❌未通过→[数据待核实]
```

禁止仅输出 URL / 标题 / 关键词：若某来源仅抓到标题与 URL 而未取到正文，须用 `extract`/`scrape`/`web_fetch` 补全全文后再写入；确实无法获取正文者标 ⚠️ 单源权威或 [数据待核实] 并注明原因。单文件承载双引擎结果，后续消费直接读取，严禁凭关键词/标题猜测或编造正文。

## 搜索轮次与终止

- 每引擎每关键词 2 轮起步，可再扩 1 轮（最多 3 轮）；3 轮后某关键词仍有缺口标「[数据待核实]」；所有缺口补足可提前终止。
- 素材使用优先级：原有需求主题 = ✅ 双引擎互证 > ✅ 多源验证通过 > ⚠️ 单源权威；冲突以更权威来源为准，无法判定标「[数据待核实]」。

## 关键词级检查点（可选，便于长任务续跑）

每关键词双引擎完成后，可在内部记录 `Kx-AnySearch done` / `Kx-Firecrawl done`（x=关键词序号）。若会话中途耗尽，可凭此仅补跑缺失/半成品关键词，不重做已完成者。
