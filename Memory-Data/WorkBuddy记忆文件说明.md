# WorkBuddy 记忆文件维护说明（权威手册）

> **本文件是 WorkBuddy 记忆系统维护的唯一权威说明。**
> 任何 Agent 只需阅读本文件，即可自主闭环地完成：
> **关联审计 → 审查 → 维护 → 纠偏（修复断链/错链、迁移错放内容、去重、重编号与索引同步）**。
> 本文件与 `memory-mgr.py` 等工具协同，但本文件优先级高于工具输出——当工具输出与本文件"已知缺陷与误报清单（§6）"冲突时，以本文件为准。

## 0. 必读纪律（开工前必看）

| # | 纪律 | 说明 |
|---|------|------|
| 0.1 | **路径核验优先** | 任何读/写/改之前，先用 `ls` 或 `Read` 核验绝对路径真实存在，禁止凭记忆拼路径。 |
| 0.2 | **严禁盲修** | `check` 命令存在**已知误报（§6）**，**绝对禁止**直接执行 `check --fix` 让程序自动删除"断链"。误报会把真实存在的文件当断链删掉。 |
| 0.3 | **备份优先** | `memory-mgr.py` 改文件前自动生成 `.bak`；人工用 `Edit`/`Write` 改前也先备份原文件。**v5.2.3 起工具写入改为原子写**——先落 `<文件>.tmp` 再 `os.replace` 换名；写入中途失败（崩溃 / 磁盘满 / 权限）时原文件**一字不动**（`.bak` 只在写入**前**生成，挡不住写入中途的截断，故需原子写补位）。 |
| 0.4 | **主↔子回链是设计中枢，不是 BUG** | 主文件索引指向子文件、子文件以 `[→主文件]` 回链，这是**合法的双向中枢模式**，`check` 报的"循环引用"绝大多数是误报（§6）。 |
| 0.5 | **单一事源** | 同一事实只在一处权威定义；他处用单向链接引用，禁止重复定义、禁止循环引用（A→B 且 B→A）。 |
| 0.6 | **先读全文件再交叉分析** | 纠偏前必须读完相关文件，确认"权威位置"与"错放位置"，再动手。 |
| 0.7 | **meta scope 例外** | `Memory-Data` 目录与 `<<主记忆文件绝对路径>>` 属元数据范畴，**排除在 AGENTS.md worktree 纪律之外**，可在主工作树直接修改，无需创建 worktree、无需 git 提交即可本地维护。 |
| 0.8 | **子记忆文件范围** | `Memory-Data` 目录中**仅有**以 `Memory-` 作为文件名开头的 `.md` 文件是子记忆文件；其他文件与本记忆系统无关。 |
| 0.9 | **记忆文件格式强制要求** | 修改 / 维护主记忆文件与任一子记忆文件时，**必须遵循 §10 的 14 条格式强制要求**（层级递进与语法、序号连续唯一、常用前置、单一事源、无重复矛盾、无歧义禁用词、引用单向且后序引用前序、引用精准唯一等）。违反即判不合规，按 §7 纠偏。 |
| 0.10 | **归属判定前置** | 新信息写入前必须先按 §3.1 判定归属：**命中 1 个子文件 → 并入**（再定位章节）；**0 命中 → 按三门槛评估新建**（须先定义四要素）；**多归属或无法唯一判定 → 暂停并询问用户**，不得自行裁决。判据来源为各子文件 YAML 的 `scope_in` / `scope_out`（规范见 §2.2；运行时视图 = 主文件写前路由卡）。 |
| 0.11 | **四要素只维护一处** | 各子文件的定位 / 角色 / 主题 / 收录范围**只在其自身 YAML 的 5 个字段中维护**（§2.2）。主文件写前路由卡、主索引区与本手册均**不承载明细**——改四要素**只改子文件 YAML**，再跑 `index` 自动重生成；**禁止**手工编辑主文件的两个工具写入区（`ROUTE_CARD` / `MAIN_INDEX`，会被整区覆盖）。 |
| 0.12 | **编号只由工具生成** | 章节编号（`## N-M` / `### N-M-X` / `#### N-M-X-Z`）**一律由 `memory-mgr.py rewrite` 生成**，禁止手工改号、手工调序。编号规则与 N 分配见 **§2.3**；`file_number` 由 `add` 自动分配（取**磁盘全部子文件 YAML 中的最大 N** + 1，v5.2.2 起不再读 state 缓存——state 可能缺失/陈旧导致分配到重复 N）；CLI 的 `--start-number` 已于 v5.2.2 **停用**（传入即报错），消除手工指定后门。手工改号会导致编号与 YAML `file_number` 不一致、跨文件锚点失同步。**例外（插章）**：向既有子记忆文件**新增**章 / 节时，按 §3.4 走**路径 A**——手工给出正确编号 + 跑 `index`，**禁止**运行 `rewrite`（其在特定结构下会静默丢弃整章）。本节禁止的是「改动**既有**编号」与「手工调序」，**不禁止** §3.4 路径 A 的新增编号。 |
| 0.13 | **编号完整性必须自检** | 任何编号变更后，**必须**跑 `check`（维度11 编号完整性）+ `断链检测.py`（锚点唯一性），两者全绿方可交付。完整保障制度（10 项判据 + 4 条纪律）见 **§3.2**。 |
| 0.14 | **占位符代入优先（移植纪律）** | 本手册路径一律用占位符 `<<主记忆文件绝对路径>>` / `<<子记忆文件目录绝对路径>>` 书写；跨机器 / 换目录后，须先按 §7.8 代入真实 P、D，再执行任何 `check` / `rewrite` / `add`；禁止直接沿用含旧路径的手册命令。 |
| 0.15 | **主文件体积控制（写入闸门）** | 主文件 `MEMORY.md` 每次会话启动即加载，其体积直接决定检索效率与记忆稀释程度。**新增内容默认不进主文件**——除「高频纪律速览」「两个工具写入区（表① / 表②）」「必要的全局指向」三类外，一律下沉到子记忆文件；主文件**不得**承载子文件已有的明细。凡产生"往主文件加一段说明"的冲动，先按 §3.1 判定归属：命中子文件即写入子文件，仅在确属全局高频纪律时才进主文件。**容量上限与截断**由 WorkBuddy 官方在代码层自动处理（超限自动压缩 / 精简），本体系**不自建**容量上限、行数上限或自动截断规则，只在**写入侧**把关。 |
| 0.16 | **本手册自包含、无外部依赖（只读本手册即可闭环）** | 本手册已内聚维护与修改整个记忆体系所需的**全部**纪律与裁定——含体系改造边界、层级裁定、表① / 表② 设计取舍、已否决方案防回潮清单（见 §1.1）。Agent **仅阅读本手册**即可独立完成对 `<<主记忆文件绝对路径>>` 与全部 `Memory-*.md` 的维护与修改，且结果与体系已敲定裁决一致。**无需**查阅任何其他文件即可开工。 |
| 0.17 | **体系外引用非法（白名单制）** | 主文件与任一子记忆文件中的链接，其目标**只允许**命中三类合法目标：子记忆文件 `Memory-*.md`、本手册 `WorkBuddy记忆文件说明.md`、主文件 `MEMORY.md`（= `断链检测.py` P-1 的 `ALLOWED_TARGETS` 白名单，见 §4.2）。指向体系外任何目录或文件（含 `Memory-Data` 目录内**非** `Memory-*.md` 的过程文档 / `.py` / `.json`）一律判**越界**，必须删除。**v5.2.1 起 `check` 维度14 已覆盖此类越界**（§6.1 D-8 标记已消解，原"check 检测不到"的表述作废），`断链检测.py` 的 P-1 转为**交叉验证**角色——二者同源，结论须一致；不一致即实现漂移，须回查单一事源。 |
| 0.18 | **路径默认值与启动期校验（v5.3.0）** | 两个工具的**默认路径一律推导、禁止硬编码用户名 / 盘符**：主记忆文件 = `<用户目录>/.workbuddy/MEMORY.md`（Python `os.path.expanduser('~')` 推导，Win11 即系统变量 `%USERPROFILE%`）；子记忆目录 = `memory-mgr.py` **自身所在目录**（`__file__` 推导，仓库迁移自动跟随）。覆盖优先级（高→低）：命令行 `--main-file` / `--sub-files-dir` > 环境变量 `MEMORY_MAIN_FILE` / `MEMORY_SUB_FILES_DIR` > 本地记录 `memory-paths.json` > 默认推导。工具在**执行初期**校验二者——主文件存在且文件名恒为 `MEMORY.md`；子目录存在且含 `Memory-*.md`（**大小写不敏感**）。不通过即向 Agent 输出精准诊断（实际值 + 原因 + 三种修正方式）并**退出码 2 中止**，不执行任何命令；校验通过的路径本地记录复用，记录失效自动回落默认推导并重写（详见 §2.1、§4.1、§4.2）。 |

## 1. 系统架构全景

```
<<主记忆文件绝对路径>>\
  MEMORY.md                          ← 主文件（YAML FM + 高频纪律速览 + 主索引表 MAIN_INDEX_START/END）

<<子记忆文件目录绝对路径>>\
  Memory-全局禁令与环境约束.md        ← 子记忆文件（file_number: 1）
  Memory-代码纪律与Git操作.md        ← 子记忆文件（file_number: 2）
  Memory-GitHub全流程操作.md         ← 子记忆文件（file_number: 3，最大文件）
  Memory-避坑铁律.md                 ← 子记忆文件（file_number: 4）
  Memory-入口能力与图谱.md           ← 子记忆文件（file_number: 5）
  Memory-多工具协同SOP.md            ← 子记忆文件（file_number: 6）
  ── 以上 6 行为 2026-09-24 快照；实际集合以目录内 Memory-*.md 动态发现为准，数量随时增减 ──
  ── 每个子记忆文件 = YAML FM（含 file_number）+ 头部速查索引表 + 编号正文（N-M-X-Z）──
  WorkBuddy记忆文件说明.md           ← 本维护手册（file_number: 0；内部章节编号独立，不参与 N-M 体系）
  memory-mgr.py                      ← 主维护工具（零依赖标准库）
  断链检测.py                        ← 只读分析工具（锚点级）
  memory-state.json                  ← 状态文件（自动生成）
  memory-changelog.json              ← 变更日志（自动生成，自包含不依赖 git）
  memory-paths.json                  ← 本地路径记录（v5.3.0：校验通过后自动写入，供复用）
```

> **子记忆文件权威定义（必须牢记）**：子记忆文件 = 目录 `<<子记忆文件目录绝对路径>>\` 内、**文件名以 `Memory-` 开头**的全部 `.md` 文件。其**数量动态增减**（体系扩展时新增、整理时删除是常态）；主文件 `MEMORY.md` 与各子文件**随时可能被修改**。上图子文件为当前快照，实际集合以目录内 `Memory-*.md` 动态为准；`memory-mgr.py` 用 `Memory-` 前缀动态发现，无需手列清单。本手册**不依赖任何外部方案/规格文档**，仅凭本文件即可闭环运维。

**数据流（中枢模式）**：
- 主文件是入口：**写前路由卡（表①）**（由子文件 YAML 四要素生成，见 §2.2）回答"新信息该进哪个子文件"，**同时**承担读前精判（见 §3.3）；**主索引表（表②）为纯定位表**——只回答"某文件的章节在哪"（三列：目标文件 / 章节位置 / 备注），**已删除**「适用场景」列，触发职能统一移交表① 的 `scope_in`（v5.1.0）。
- 子文件是权威内容载体：每个子文件 = YAML Front Matter + 头部速查索引表 + 正文（连续编号章节）。
- 双向链接合法：主→子（索引/引用）、子→主（`[→主文件]` 回链）、子→子（单向引用）。**只有"子↔子互相引用形成环"才是真违规**。

### 1.1 体系边界、层级裁定与已否决方案（结构性改造前必读）

> **用途**：界定本体系的改造边界与层级关系，并列出**已否决、不得重新提出**的方案。凡计划对体系做结构性调整（增删子记忆文件、调整表① / 表②、调整加载策略），**先读本节**——避免推翻既有裁决、避免重新引入已被否决的设计。

**① 体系边界（改造对象）**

| 项 | 裁定 |
|---|---|
| 边界 | 本体系 = 主文件 `<<主记忆文件绝对路径>>` + 子记忆文件 `<<子记忆文件目录绝对路径>>\Memory-*.md`，**仅此二者** |
| 不涉及的层 | 不涉及 WorkBuddy 官方三层记忆体系（L1 云端 / L2 用户级本地 / L3 工作区）的其他层；**不要求**与官方三层对齐 |
| 主文件身份 | 主文件即官方 L2 文件，被特异化为**瘦路由索引**——只做入口与路由，不承载明细（写入闸门见 §0.15） |
| 体积目标 | 主文件每次会话启动即加载，须**控制膨胀**：膨胀直接导致检索效率下降与记忆稀释 |

**② 层级裁定（关键：子文件不是独立层级）**

- 子记忆文件 `Memory-*.md` 是主文件索引的**细分子层**，**不是**独立于主文件的层级。
- **禁止**引入「ROM / RAM / Disk / Tape」之类把主文件与子文件拆为多个并列层级的多层模型——该模型已被否决，根因是**把细分误当作分层**。
- 体系内**不设**历史可追溯机制（不记录每条记忆的变更履历）。

**③ 已否决方案清单（不得重新提出）**

| # | 已否决方案 | 否决理由 / 替代做法 |
|---|---|---|
| 1 | 多层级分层模型（ROM / RAM / Disk / Tape 等） | 把细分误当作分层；子文件是主文件的细分子层（见 ②） |
| 2 | 与官方 L1 / L2 / L3 三层体系对齐 | 改造对象不含官方体系，无需对齐 |
| 3 | 引入历史可追溯机制 | 明确不需要（见 ②） |
| 4 | `Active Context`（2-3 个热文件常加载） | 明确不需要；加载一律依 §3.3 的二值判定 |
| 5 | 索引压缩为「一句话索引」 | 索引须承载完整章节位置（表② 全量 H2），压缩会损失定位精度 |
| 6 | 新增 `Start_Memory.md` 等独立入口文件 | 入口唯一是主文件，不新增入口 |
| 7 | 表② 增设「强制级别」列 | 读前判定为**二值**（命中即加载 / 未命中不加载），不设分级 |
| 8 | 表② 增设「高频章节优先跳转提示」 | 不分级；场景词已含于 H2 标题内 |
| 9 | 合并表① ROUTE_CARD 与表② MAIN_INDEX | `scope_in` 已承担触发职能，合并动因消失；二者职能不重叠（见 §3 约定 9） |
| 10 | 把「MAIN_INDEX 全量 H2 / 索引膨胀」判定为问题 | 全量 H2 是**精度手段**；允许合理的索引膨胀 |
| 11 | 插章后运行 `rewrite` 由工具补编号 | 会编号碰撞并静默丢弃整章（见 §3.4）；走路径 A 手工编号 |
| 12 | 在子文件 YAML **新增加载策略类字段**（`load_policy` / `trigger_when` / 分级必读标记等） | 加载判据恒为四要素的 `scope_in`（§2.2 ①），另立字段必致**双源漂移**——改了 `scope_in` 却忘改该字段，D-9（标题/索引失真）类故障重演；且违反 §2.2「四要素是归属判定唯一权威定义源」的单一事源。**替代做法**：需要更强的触发表达时，按 §2.2 ① 把 `scope_in` 写成「触发情境 + 知识主题」复合态；需要表达强制性时按 §3.3 ③ 走**二值判定**（命中即加载 / 未命中不加载），二者均不新增字段 |
| 13 | 表②「备注」列填写"高频 / 常用 / 优先看"等提示 | 备注列唯一合法填值是**结构性例外指引**（见 ④）；此类提示属已否决的「高频章节优先跳转提示」（见本清单第 8 项） |

**④ 表① / 表② 的设计取舍**

| 项 | 裁定 |
|---|---|
| 是否合并表①与表② | **不合并** |
| 表① 职能 | 承载 `scope_in` / `scope_out` **全量明细**，同时承担「写前入库判定」与「读前精判」双重职能（见 §3.3 ④） |
| 表② 职能 | **纯定位表**（三列：目标文件 / 章节位置 / 备注），保留**全量 H2**，不截断、不做部分加载 |

| 表②「备注」列填值纪律 | **唯一合法填值 = 结构性例外指引**——仅当某个 H2 序列需要二次索引入口时才标注。现行唯一实例：超大文件（如 `Memory-GitHub全流程操作.md`）降级指向「文件头部速查索引表」，见 §3.3 ⑤。**禁止**填"高频""常用""优先看""推荐"等提示——此类提示属已否决的「高频章节优先跳转提示」（见 ③ 第 8、13 项）；**其余一律留空**。本列由 `index` 生成，改填值规则须改 `memory-mgr.py` 的生成逻辑，**不得手工编辑主文件该区**（§3 约定 6） |

### 2.2 子记忆文件四要素（字段规范 · 归属判定的唯一权威定义源）

> **用途**：新信息入库前，按各子文件的「收录（in-scope）」锁定目标子文件——**命中 1 个** → 并入该文件（再定位章节）；**命中 0 个** → 评估新建；**命中 ≥2 个** → 暂停并询问用户。完整判定流程见 §3.1。
> **单一事源**：各子文件的定位 / 角色 / 主题 / 收录范围，**只在其自身 YAML Front Matter 的 5 个字段中权威定义**（就近维护、随文件生命周期走）。主文件「写前路由卡」与本节**均不承载明细数据**——明细由工具生成，彻底消除人工同步成本。

**① 字段规范（子文件 YAML 必填 6 项 = 5 四要素 + 1 文件编号）**

| 字段 | 语义 | 写法要求 |
|------|------|---------|
| `file_number` | **文件编号（N）**：该文件在编号体系中的 N 值 | 非负整数；手册=0、子记忆文件从 1 起；**由 `add` 自动分配（取当前最大 N + 1），禁止手工指定**；参与章节编号（§2.3），不参与归属判定 |
| `positioning` | **定位**：这个文件是什么 | 一句话，单行不换行 |
| `role` | **角色**：承担哪一层职能 | 取自层级枚举：硬约束层 / 编码规范层 / 作业流程层 / 经验教训层 / 能力台账层 |
| `theme` | **主题**：覆盖的领域范围 | 用 ` / ` 分隔 3~6 个主题词 |
| `scope_in` | **收录范围**（in-scope） | 用 `；` 分隔具体条目；**每条须写成「触发情境 + 知识主题」复合态**——例：「执行 git 破坏性操作时（强推 / 删 main / 删受保护分支）」「要调用 dynamic-mcp 或查可用工具分组时（调用三步 + 分组清单）」。**禁止**纯名词条目（如仅写「git 操作 / 工具链」）：纯名词会造成词形距离与语义转换成本，直接削弱 §3.3 第 1 步读前精判的命中率 |
| `scope_out` | **不收录范围**（out-of-scope） | 用 `；` 分隔，且**每项须以 `→` 指向应去的子文件**（防边界漂移） |

**② 生成链路（单向数据流，无人工同步）**

```
子文件 YAML 的 5 个四要素字段  ←── 唯一数据源（人工就近维护，改四要素只改这一处）
                        （第 6 字段 `file_number` 不参与路由卡生成，规范见 §2.3）
        │
        ├─ memory-mgr.py index ──► 主文件 <!-- ROUTE_CARD_START/END --> 写前路由卡（派生视图）
        └─ memory-mgr.py check 维度10 ──► 四要素缺字段告警（WARN 级）
```

- 主文件路由卡**禁止手工编辑**：`index` 会整区重建，手工修改将被覆盖（同主索引区规则，见 §3 约定 6、7）。
- 本手册**不列四要素明细**：要看明细，读主文件路由卡（运行时视图），或直接读目标子文件 YAML（权威源）。
- 四要素是**子文件**的必填项；主文件 `parent: null`，不需要四要素。

**③ 边界判据（易混项裁决）**

| 易混对 | 判据 |
|--------|------|
| 能力台账（子文件5） vs 作业流程 | 子文件5 回答"**有什么工具、单个工具怎么调**"；若内容回答"**多个工具按什么步骤协同、失败如何降级、分几个场景**"，则属作业流程，子文件5 不收录，须按 §3.1 第 3 步评估新建 |
| 规则条文（子文件1、2） vs 坑案例（子文件4） | 前者回答"**必须怎么做**"（规范）；后者回答"**曾经踩过什么坑、怎么修**"（案例）。同一事项的规则与案例分置两文件，各自权威 |
| GitHub 流程（子文件3） vs 通用代码写法（子文件2） | 凡**绑定 git / gh 命令或平台机制**的步骤 → 子文件3；与平台无关的编码纪律 → 子文件2 |

> **新增子文件时**：必须先按 §3.1 第 3 步定义上述 5 个字段并写入新文件 YAML，再执行 `add`（工具参数见 §7.6）。字段缺失由 `check` 维度 10 报警，路由卡对应单元格显示 `[待补]`。

### 2.3 章节编号规范（v5.0.0 重构 · 编号体系唯一权威定义源）

> **适用范围**：全部**子记忆文件**（`Memory-*.md`）。本手册自身编号独立（§0~§11），**不适用**本节。

**① 编号格式（三层，一律用连字符分隔）**

| 层级 | 语法 | 语义 | 实例 |
|---|---|---|---|
| 章（H2） | `## N-M 标题` | N = 文件编号；M = 本文件内章序 | `## 3-10 gh 能力速查` |
| 节（H3） | `### N-M-X 标题` | X = 本 M 内节序 | `### 3-10-8 发布与制品` |
| 小节（H4） | `#### N-M-X-Z 标题` | Z = 本 X 内小节序 | `#### 3-13-3-1 git 推送失败的两类情形` |

**H1 不参与编号**；体系中**不再使用**"第X篇"这类篇标题。

**② 编号分配规则**

- **N（文件编号）**：手册 = 0；子记忆文件从 1 起顺序分配（当前：1 = 全局禁令、2 = 代码纪律、3 = GitHub、4 = 避坑铁律、5 = 入口能力、6 = 多工具协同SOP）；**新建文件取当前最大 N + 1**（故从 7 起延续）；删除文件只腾空该 N，**不动其他文件编号**。上述映射为**当期快照**，N 的权威取值一律以各文件自身 YAML 的 `file_number` 字段为准。
- **M / X / Z**：各自在**父级内**从 1 开始、连续、不重复、不跳号；**只在本文档内有意义，不跨文件继承**。
- **H4 存在则编、不存在不造**（当前仅 `Memory-全局禁令与环境约束.md` 与 `Memory-GitHub全流程操作.md` 含 H4）。

**③ 分隔符必须用连字符 `-`（硬性）**

原因：GFM 锚点规则会**删除点号**。若写成 `## 3.10`，编辑器算出的锚点是 `310-...`，而工具按保留连字符算出 `3-10-...`——两者不一致，会产出「工具校验通过、编辑器点击不跳」的**假通过**。写成 `## 3-10` 则两侧一致。

锚点换算示例：`## 1-2 全局禁令（最高优先级）` → `#1-2-全局禁令最高优先级`。

**④ 唯一性要求**

编号须**不重复、不跳跃、不乱、唯一**。由 `check` 维度 11 自动校验（判据见 §3.2）；**禁止手工改动既有编号**（§0.12）。**例外（插章）**：为**新增**章 / 节手工编号且不引起既有编号位移时，按 **§3.4 路径 A** 执行（手工编号 + `index`，**禁止** `rewrite`）——此为例外而**非**违反本条。

## 3. 核心约定与核心纪律（纠偏时必须遵守）

> 本节含两部分：**约定 1~9**（跨场景通用规矩）与 **§3.1~§3.4**（四项独立制度，各有唯一权威定义权）。

1. **绝对路径双轨制**：主文件在 C 盘、子文件在 D 盘，跨盘符**必须**用绝对路径（`file:///D:/...` / `file:///C:/...`）。相对路径无法跨盘。
2. **章节编号（v5.0.0 重构）**：`## N-M` / `### N-M-X` / `#### N-M-X-Z`——N 为文件编号，M / X / Z 为各自父级内从 1 起的顺序号；**编号只在本文档内有意义，不跨文件连续**；分隔符**必须用连字符 `-`**（点号会被锚点规则删除）；H1 不参与编号。完整规范见 **§2.3**。
3. **锚点格式（GFM）**：全小写、空格换连字符、去特殊字符（**点号会被删除**，故编号必须用连字符）。例：`## 1-2 全局禁令` → `#1-2-全局禁令`；`### 1-2-1 禁止强推` → `#1-2-1-禁止强推删除自家main`。
4. **单一事源**：同一事实只在一处权威定义；他处用**单向**链接引用，禁止重复定义、禁止 A↔B 循环引用。
5. **YAML 字段**：所有文件均须 8 个必填字段 `title` / `topic` / `tags` / `related` / `scope` / `created` / `updated` / `parent`（子文件 `parent: "MEMORY.md"`，主文件 `parent: null`）；**子文件另须 6 个字段** = 5 个四要素字段 `positioning` / `role` / `theme` / `scope_in` / `scope_out`（规范见 §2.2）+ 1 个编号字段 `file_number`（规范见 §2.3）。字段缺失分别由 `check` 维度 10 / 维度 11 报警。四要素是主文件写前路由卡的唯一数据源，**只改子文件 YAML 一处即可**，无需同步手册或主文件；`file_number` **由 `add` 自动分配（取当前最大 N + 1）**，禁止手工指定。
6. **主文件的工具写入区（路由卡区 + 主索引区，均禁止手工编辑）**：主文件有两个由工具重建的区块——`<!-- ROUTE_CARD_START -->`…`<!-- ROUTE_CARD_END -->`（写前路由卡，由 `index` 从子文件 YAML 四要素生成，见 §2.2）与 `<!-- MAIN_INDEX_START -->`…`<!-- MAIN_INDEX_END -->`（主索引表）。**主索引区只收子记忆文件条目——设计需要，非缺陷**：`index` / `sync` / `add` 重建该区域时，**仅遍历 `Memory-*.md` 子记忆文件生成条目**——主索引的职能即"子记忆文件路由表"，这是**设计需要**。由此得出四条推论（前三条针对主索引区，第四条对两区同时成立）：
   - **不得手工编辑这两个区间**。区间内容由工具整区重建，手工修改将在下次 `index` 时被覆盖；
   - 区间内指向**非子记忆文件**的条目（含指向本手册的条目）在重建时会被清除，属**预期行为**，不得据此判定工具异常；
   - **不得依赖主索引承载本手册入口**。本手册入口须固化在子记忆文件章节内（见 `Memory-入口能力与图谱.md` 的「memory-mgr.py 维护工具」章节），或依赖 SOUL.md「记忆文件维护门禁」中给出的硬编码绝对路径；
   - **路由卡区的唯一数据源是子文件 YAML 的四要素字段**（见 §2.2）。改四要素**只改目标子文件 YAML**，再跑 `index` 重生成；直接改主文件路由卡或本手册都会造成双源，前者被覆盖、后者与本手册"不列明细"的约定冲突。
7. **子文件头部索引区**：子文件内 `> **本文件速查索引**` 到 `<!-- INDEX_END -->` 之间是工具写入区。
8. **归属判定前置（新信息入库必做）**：任何新信息写入主文件或子文件之前，**必须先按 §3.1 判定归属**；判定结果不唯一（0 命中且不满足新建门槛，或多归属）时**暂停并询问用户**，不得直接写入。
9. **表① 与表② 不合并、职能不重叠**：表① ROUTE_CARD 承载 `scope_in` / `scope_out` **全量明细**（明细保留在主文件中，不做精简），同时承担「写前入库判定」与「读前精判」双重职能（见 §3.3 ④）；表② MAIN_INDEX 为**纯定位表**（三列：目标文件 / 章节位置 / 备注），保留全量 H2。**禁止**合并二者、**禁止**在表② 增设「强制级别」列或「高频章节优先跳转提示」——读前判定为**二值**（命中即加载 / 未命中不加载），不设中间级别。设计取舍的完整裁定见 §1.1 ④。

### 3.1 归属判定规则（新信息入库决策树）

> **权威性**：本节是"新信息该放到哪里"的**唯一定义处**；判据来源是各子文件 YAML 的 `scope_in` / `scope_out` 字段（字段规范见 §2.2；运行时视图 = 主文件写前路由卡）。**禁止**跳过本节直接执行 `add`（工具调用见 §7.6）。

**输入**：一条待入库的新信息（来自素材文件、对话结论、工作日志、外部资料等）。
**输出**：① 并入既有子文件（含目标章节）；② 新建子文件（含新文件四要素）；③ 暂停并询问用户。

**第 0 步 · 预处理**：把新信息提炼为「主题短语 + 3~6 个关键词」，剔除一次性任务痕迹（日期、临时路径、单次执行结果）。

**第 1 步 · 匹配既有子文件**（判据 = 各子文件 YAML 的 `scope_in`，经主文件写前路由卡「收录（in-scope）」列呈现）
- 命中 **1** 个 → 进入第 2 步；
- 命中 **0** 个 → 进入第 3 步（新建评估）；
- 命中 **≥2** 个 → 进入第 4 步（多归属，暂停询问）。

**第 2 步 · 定位到章节**（仅在目标子文件内部）
1. 用该子文件头部速查索引表定位候选 `## N-M` / `### N-M-X`（大文件先用 `get-offset`，禁止全量灌入上下文）；
2. 校验单一事源（§3 约定 4）：
   - 目标章节**已有同一事实** → **不新增**，改为就地**补充 / 修订**该处，避免重复定义；
   - 无同一事实但章节主题覆盖 → 在该章节内**增补段落或 `### N-M-X`**；
3. 目标子文件**无任何章节覆盖该主题** → 在该文件内**新增 `## N-M`**——**编号方式与工具路径一律按 §3.4 裁决**：追加式新增（不引起既有编号位移）走**路径 A**（手工给出正确编号 + `index`，**禁止** `rewrite`）；仅当插入位置引起编号连锁位移时走**路径 B**（`rewrite`）。**注意**：本条**不适用**"编号由工具生成、禁止手工指定"的通用表述——该表述在插章场景下与 §3.4 冲突，**以 §3.4 为准**；
4. 出现 **≥2 个章节均可承载且无法择一** → 进入第 4 步。

**第 3 步 · 新建子文件评估**（三个门槛须**同时**满足）

| 门槛 | 判据 | 不满足的处置 |
|---|---|---|
| ① 独立性 | 主题不落入任一既有子文件的 in-scope（已由第 1 步 0 命中确认） | 回到第 2 步重新定位 |
| ② 可复用性与体量 | 内容是**跨会话可复用的规则 / 流程 / 事实**，且体量足以独立成篇 | 并入主题最近的子文件相应章节 |
| ③ 无冲突 | 不构成对既有子文件权威章节的重复定义 | 按 §7.3 改为单向引用 |

**通过三门槛后，新建前必须先定义「四要素」**（写入新子文件 YAML 的 5 个字段；规范见 §2.2）：
1. **定位**：一句话——这个文件是什么；
2. **角色**：承担哪一层职能（硬约束层 / 编码规范层 / 作业流程层 / 经验教训层 / 能力台账层）；
3. **主题**：覆盖的领域范围；
4. **收录范围**：明确列出 in-scope 与 out-of-scope；out 项须**指向应去的子文件**，防止边界漂移。

> 四要素未定义完成，**不得执行 `add`**。新增后**无需**手工同步手册或主文件——`add` 内部会调 `index`，把新子文件的四要素自动并入主文件写前路由卡。

**第 4 步 · 暂停与询问（用户裁决前置）**

**触发条件**（满足任一条即暂停，不得自行裁决）：
1. 第 1 步命中 0 个，但第 3 步三门槛未同时满足（含"体量不足以独立成篇"却无合适归属）；
2. 多归属：命中 ≥2 个子文件或 ≥2 个章节，且无法用各子文件的 `scope_out` 排除；
3. 与既有权威章节存在潜在重复，但无法判定哪一处为权威；
4. 内容涉及隐私 / 凭证 / 敏感信息（先过「入库隐私闸门」，权威定义见 `Memory-全局禁令与环境约束.md`，本节不重复定义）；
5. 内容涉及体系外文件（越界引用风险，见 §6 D-8）。

**暂停时的输出要求**（缺一不可）：
- **事由**：卡在哪一步、哪一条判据；
- **解释**：为何无法唯一判定（列出各候选的命中点与排除障碍）；
- **候选方案**：给出 2~3 个可选归属，标注**推荐项**及其理由；
- **影响面**：各方案对章节编号、索引、跨文件锚点的影响。

**用户裁决后**：按裁决执行，并在 §7.6 的操作记录中注明"归属经用户裁决"。

### 3.2 编号完整性保障制度（10 项判据 + 4 条纪律）

> **目的**：保障编号**不重复、不跳跃、不乱、唯一**（§2.3 ④）。编号是章节定位锚的唯一来源，一旦错乱将连带锚点失效。

**① 10 项判据（工具自动校验）**

| # | 判据 | 级别 | 校验方 |
|---|---|---|---|
| 1 | `file_number` 存在（每个子记忆文件 YAML 必有） | ERROR | `memory-mgr.py` 维度11 |
| 2 | `file_number` 全局唯一（无两份文件同 N） | ERROR | `memory-mgr.py` 维度11 |
| 3 | `file_number` 取值合法（非负整数） | ERROR | `memory-mgr.py` 维度11 |
| 4 | 章编号前缀与 YAML `file_number` 一致（`## N-M` 的 N 必须等于该文件 YAML 值） | ERROR | `memory-mgr.py` 维度11 |
| 5 | 章 M 在本文件内从 1 起连续、不重复、不跳号 | ERROR | `memory-mgr.py` 维度11 |
| 6 | 节 X 在所属 `## N-M` 内从 1 起连续 | ERROR | `memory-mgr.py` 维度11 |
| 7 | 小节 Z 在所属 `### N-M-X` 内从 1 起连续 | ERROR | `memory-mgr.py` 维度11 |
| 8 | 层级从属正确（`###` 必挂 `##` 之下、`####` 必挂 `###` 之下） | ERROR | `memory-mgr.py` 维度11 |
| 9 | 编号格式合法（匹配 `^\d+(-\d+)*\s`） | ERROR | `memory-mgr.py` 维度11 |
| 10 | **锚点唯一性**（同一文件内锚点不重复，防层级坍缩碰撞） | ERROR | `断链检测.py` |

**职责划分依据（单一事源）**：`memory-mgr.py` 负责**格式级 + 结构级**（它生成编号，生成与校验同源）；`断链检测.py` 负责**链接级**（已有 `anchor_set`，天然可查重复）。

**② 4 条纪律（人工必守）**

| # | 纪律 | 说明 |
|---|---|---|
| 1 | **新建必写 `file_number`** | 由 `add` 自动分配（取当前最大 N + 1），禁止手工指定；手工创建文件须先跑 `number --init` 补齐。 |
| 2 | **改动既有编号必须走 `rewrite`** | 禁止手工改**既有**号（§0.12）。`rewrite` 自动同步跨文件与同文件锚点，并重建索引。**例外（插章）**：为**新增**章 / 节手工编号时，按 **§3.4 路径 A** 执行（手工编号 + `index`，**禁止** `rewrite`）——本条与 §3.4 冲突时**以 §3.4 为准**。 |
| 3 | **双绿方可交付** | 任何编号变更后必须跑 `check` + `断链检测.py`，两者全绿才算完成。 |
| 4 | **编辑器抽样验证** | 编号变更后须在 Markdown 编辑器中**实际点击 ≥3 条锚点链接**确认能跳转——工具校验不了编辑器行为，此项专治「工具绿、点击死」。 |

**③ 编号变更标准流程**

> **前置裁决（必读，先分流再执行）**：本流程**仅适用于「改动既有编号」**。若为向子记忆文件**新增**章 / 节（插章），
> 先按 **§3.4** 裁决路径：不引起既有编号位移 → 走**路径 A**（手工正确编号 + 只跑 `index`，**禁止** `rewrite`），
> **不得**执行下列 `rewrite` 步骤；仅当插入位置引起编号连锁位移 → 走**路径 B**（下列流程 + 逐章核验正文完整性）。
> 误跑 `rewrite` 的后果是**编号碰撞并静默丢弃整章正文**，且 `check` 全绿不报警（§3.4 制定动因）。

```bash
uv run ... memory-mgr.py --no-interactive rewrite --dry-run   # 预览新旧编号映射与锚点映射
uv run ... memory-mgr.py --no-interactive rewrite             # 执行（含跨文件 + 同文件锚点同步）
uv run ... memory-mgr.py --no-interactive index               # 重建主索引与各文件头部索引
uv run ... memory-mgr.py --no-interactive check               # 维度11 编号完整性
uv run ... python 断链检测.py                                  # 锚点唯一性 + 链接可达性
# [人工] 编辑器抽样点击 3 条锚点链接
```

### 3.3 读前加载纪律（把加载策略显式化，终结对 Agent 自律的隐式依赖）

> **制定动因**：主文件长期缺乏针对子记忆文件的**显式加载策略**——何时该加载哪个子文件，
> 完全依赖 Agent 凭文件名字面与经验判断。这推高了加载决策成本、放大了随意加载性，
> 并使加载行为在多次会话间不可复现。本节将加载策略显式化、纪律化。

**① 适用范围**：凡需决定是否加载某个子记忆文件（及其章节）的场景，一律按本节执行。

**② 三步单向流程（严禁循环）**

> **表述一致性（本节为权威定义）**：主文件 `MEMORY.md` 规则三把第 3 步的 3a / 3b 拆列为 ③④，表述为「四级定位链」。二者**实质等价**（本节 3a / 3b = 其 ③④），**本节为权威定义**；后续若统一两处字面表述，以本节为准修改主文件。

```
第 1 步 · 精判  ──► 判据：主文件表① ROUTE_CARD 的「收录（in-scope）」列
                    （数据源 = 各子文件 YAML 的 scope_in 全量条目）
                    双向校验【强制】：以 scope_in 命中纳入候选后，**必须**再以
                    「不收录（out-of-scope）」列（= 各子文件 YAML 的 scope_out）
                    复核排除——scope_out 每项已标 `→` 指向应去的子文件。
                    只纳入不排除会造成误加载。
                    输出：命中的单个或多个子记忆文件
                          ↓
第 2 步 · 定位  ──► 判据：主文件表② MAIN_INDEX 的「章节位置」列（全量 H2）
                    以任务描述匹配候选文件的 H2 标题，最优匹配者**同时确定**
                    目标文件与目标章节（由多个候选收敛至单个）
                    注：精判已命中单个文件时，本步仍须执行，用于锁定到具体 H2
                          ↓
第 3 步 · 读取  ──► 3a【强制 · 先索引】先读该子文件头部的「本文件速查索引」
                    （起于 `> **本文件速查索引**`，止于 `<!-- INDEX_END -->`），
                    据其锁定到 ### H3 级别
                3b get-offset 取得该 H3 的行号范围
                    → Read(offset, limit) 精准读取，**禁止**整文件全量灌入上下文
```

> **单向约束**：流程只能 ①→②→③ 前进。**严禁**在推进后回退至前序阶段重查（如"查完③再回①复核"），
> 此类回退即构成**循环查找**，必须禁止。**零命中时不回查**——直接判定"本任务无需加载记忆"。

**③ 加载粒度与触发语义（二值，无中间级）**

- **粒度**：以**整个 H2 章节**为最小加载单位；加载即加载该 H2 全部内容，**禁止**只截取 H2 内部片段。
- **触发语义**：**命中即加载，未命中不加载**——二值判定，**不设**"建议 / 可选 / 高频优先"等中间级别。

> **元任务特例（直连条款）**：当任务本身指向**记忆体系的整理 / 维护 / 审计 / 改造**时
> （如"整理记忆体系""维护 MEMORY.md""审计记忆文件"），**不适用常规精判**——直接加载
> 本手册与子文件5 的 memory-mgr.py 章节，不逐条匹配 `scope_in`。原因是此类任务的判据
> 即体系自身，经 `scope_in` 匹配反而可能零命中或误命中。

**④ 表①一物两用，但两用的裁决规则不同（最高频误用处，必读）**

表① ROUTE_CARD 同时承载「写前入库判定」与「读前精判」两项职能，**共用同一份 `scope_in` 判据**，
但多命中 / 零命中下的处置规则不同，混用即为错误：

| 命中情况 | 写前入库判定（新信息往哪放） | 读前精判（干活时去哪取） |
|---|---|---|
| 命中 1 个 | 并入该文件（再定位章节） | 锁定该文件，进入第 2 步 |
| 命中 ≥2 个 | **暂停并询问用户**（只能放一处，须唯一） | **全部纳入候选**，进第 2 步靠 H2 匹配收敛（**可**读多个，**不询问**） |
| 命中 0 个 | 按 §3.1 第 3 步评估新建子文件 | **不加载任何子记忆文件**，直接执行任务 |

> **最高频误用**：把写前的「多命中须暂停询问」误用到读前，导致读一个文件也要打断用户。
> **读前多命中不询问**，靠章节匹配自行收敛。

**⑤ 子文件头部速查索引：强制先读（不可跳过）**

各子记忆文件头部均含工具生成的「本文件速查索引」（起于 `> **本文件速查索引**`，
止于 `<!-- INDEX_END -->`），其粒度覆盖 **H2 + H3**；而主文件表② MAIN_INDEX 的
「章节位置」列**仅列 H2**（`_generate_main_index()` 取 `level == 2`）。二者粒度互补、
构成「章 → 节」两级定位，**不可互相替代**：

| 载体 | 粒度 | 作用 |
|---|---|---|
| 表② MAIN_INDEX 章节位置列 | 仅 H2 | 跨文件粗定位（锁定章） |
| 子文件头部速查索引 | **H2 + H3** | 文件内细定位（锁定节） |

> **故：读取子文件内容前，必须先读该文件头部速查索引**，据其再 get-offset 到 H3。
> 跳过速查索引直接读正文、或整文件全量加载，均判违规。
> 对超大文件（如 `Memory-GitHub全流程操作.md`，速查索引 108 行、表② 已降级指向
> 「文件头部速查索引表」），速查索引是唯一可行的细粒度入口，更不可跳过。

**⑥ 纪律效力**

本节是**加载行为的唯一定义源**。Agent **不得**凭文件名猜测是否加载，必须经第 1 步判据匹配。
违反本节（含回退重查、未命中仍加载、只截片段、跳过速查索引、整文件全量加载）即判不合规，按 §7 纠偏。

### 3.4 插章编号路径与验收纪律（新增章节时的强制路径）

> **制定动因（v5.2.1 据实测修正定性）**：`rewrite` 在「已存在 `## N-M`（含子节）+ 新插入 `## N-(M+1)`（含子节）」结构下会发生**编号位移 + 跨文件锚点错配**，且当时 `check` 12 维度仍报全绿、不报警（实证见子文件4 `### 4-4-1`）。**定性修正说明**：v5.2.1 前的手册表述为"静默丢弃整章正文"，实测（逐行比对 `_renumber_content` 输入输出）表明**正文一行不丢**，真实故障是——① 插入使后续章编号整体位移；② `_collect_headings_for_anchor` 按 H2/H3/H4 **分组**收集（而非文档顺序），导致新旧标题按位置 zip 配对时**错配**，把跨文件链接的锚点改写到错误的标题上。表现为主索引 / 子文件链接跳错位置，观感等同"章节消失"。**根因已于 v5.2.1 修复**（改为文档顺序收集 + 文本序列不一致显式告警），但本节的**路径裁决仍然有效**——路径 A 仍是首选，因为它根本不触发重编号。而 §0.12、§2.3 ④、§3.2 ②-2 / ③、§5 维度11 解读、§7.3、§7.5、§7.6、§8 等处的**通用表述**均要求"编号由工具生成 / 编号变更走 `rewrite`"——两条纪律在插章场景下直接冲突。本节给出裁决路径。

> **优先性（全手册统一，勿被通用表述带偏）**：**本节裁决优先于本手册中一切「编号由工具生成 / 编号变更必须走 `rewrite` / 禁止手工编号」的通用表述**，前述各节处已逐一加注 §3.4 例外导流。判据只有一条：**是否改动既有编号**——不改（新增且不位移）→ 路径 A；改（连锁位移）→ 路径 B。任何一处与本节冲突，**以本节为准**。

**① 路径裁决（按插入位置二选一）**

| 插入位置 | 是否引起既有编号位移 | 采用路径 |
|---|---|---|
| 章末追加节（`### N-M-X`）、文件末追加章（`## N-M`） | **否** | **路径 A：手工正确编号**——**禁止**运行 `rewrite` |
| 文件中部插入（导致后续章 / 节编号连锁 +1） | **是** | **路径 B**：先整体备份，再按 §3.2 ③ 走 `rewrite`，跑完**必须逐章核验正文完整性**（见 ③ 第 4 项） |

**② 路径 A 四步（默认路径，覆盖绝大多数场景）**

1. **备份**：`cp <子文件> <子文件>.bak-<日期>-<事由>`（§0.3）。
2. **编号落位**（v5.2.1 起**由工具算、人工写**）：先跑 `next-num` 取号——

   ```bash
   uv run ... memory-mgr.py --no-interactive next-num --file "Memory-x.md" --level 2
   uv run ... memory-mgr.py --no-interactive next-num --file "Memory-x.md" --level 3 --after "N-M"
   uv run ... memory-mgr.py --no-interactive next-num --file "Memory-x.md" --level 4 --after "N-M-X"
   ```

   该命令返回①下一个可用编号 ②应走路径 A 还是 B（`--after` 指**同级**标题且其后仍有同级 → 判 B；指**父级**或省略 → 判 A）。口径：H2 取本文件现有最大 `M` + 1；H3 在所属 `## N-M` 内取现有最大 `X` + 1；`####` 取 `Z` + 1，编号须**连续、不跳号、不重复**（§2.3 ④）。回链 `[→主文件]` 保持在文件末尾，新章插在其**之前**。
   > 取号工具化前，Agent 只能肉眼数编号，既易错又与「编号由工具生成」的通用表述形成方向性冲突；`next-num` 消解该冲突——**计算由工具给，写入仍由人工做**（写入动作不交给工具，是因为 §3.4 的安全边界是「只改索引区、不改正文」）。
3. **同步四要素**（仅当新章引入新的收录主题时）：按 §0.11 只改该子文件 YAML 的 `scope_in`；**当且仅当**新章主题词**无法**被既有 `theme` 的 3~6 个主题词完整涵盖时，同步追加 `theme`（判据：逐词比对能否涵盖——能则不改，不能则追加）。**禁止**手工改主文件的两个工具写入区。
4. **跑 `index`** 重建索引——`index` 只改索引区、不改正文，这是路径 A 的安全边界。

**③ 五项验收（缺一不可；路径 A / B 均适用）**

```bash
# 1 完整性检查（14 维度）
uv run ... memory-mgr.py --no-interactive check
# 2 链接级检测（断链 / 越界 / 回链 / 锚点唯一性）
uv run ... python 断链检测.py
# 3 综合校验（含索引一致性）
uv run ... memory-mgr.py --no-interactive validate
# 4 逐章核验正文完整性
grep -nP "^#{2,3} " <子文件>
# 5 确认改动未被还原
git status --short
```

> **一键等价命令（v5.2.1）**：上述五项已可由 `uv run ... memory-mgr.py --no-interactive verify` 一次跑完并输出汇总表（第 4 项改为「磁盘章节数 ↔ 状态文件记录」比对，第 5 项输出变更条数）。**但第 4 项的"正文是否缺失"仍须人工过目**——工具只能比对章节**数量**，无法判断某章正文是否被掏空，故路径 B 之后仍建议按上表第 4 项逐章 `grep` 复核（实证见子文件4 `### 4-4-2`）。

> **第 4 项不可省**：`check` 绿 ≠ 内容完整。`check` 只查格式 / 编号 / 锚点，**不查正文是否缺失**；丢章只能靠逐章 grep 比对或 `断链检测.py` 暴露（实证见子文件4 `### 4-4-2`）。
> **第 5 项不可省**：见 ④。

**④ `.md` 与两个 `.py` 均受版本控制（v5.3.0 起）**

本仓库中，子记忆文件与本手册（`.md`）**受 git 跟踪**，存在被还原到 HEAD 的风险；`memory-mgr.py` / `断链检测.py`（`.py`）**自 v5.3.0 起同样纳入 git 跟踪**（此前因 `.gitignore` 的 `Memory-Data/*` 规则不受跟踪，该表述作废）。故改完 `.md` **或 `.py`** 后**必须**执行验收第 5 项确认改动留存；一旦发现被还原，须从改前备份重新应用改动。

**⑤ 验证中文内容落位必须用 `Read`**

本机 `PowerShell` 的 `Get-Content` + `Select-String` 匹配中文会因默认编码返回 0 命中——据此判定"内容未落位"会得出**错误结论**（曾据此误判主文件规则三未落位，实为已落位）。验证中文内容（标题、条文、四要素）是否真实落位，**必须用 `Read` 工具读取实际行**，不得依赖命令行中文检索。

## 7. 纠偏手册（模块化 SOP）

> 每条 SOP 都是"识别 → 决策 → 执行 → 验证"闭环。执行前先 `ls` 核验路径。

### 7.1 修复断链（链接目标文件不存在）

**识别**：`check` 维度3 报告 `[维度3] xxx 断链: file:///...不存在路径`，且 `ls` 确认目标确实不存在。
**决策**：
- 若目标文件**应存在**（只是路径写错）→ 改链接路径为正确绝对路径。
- 若目标文件**已改名/迁移** → 改为指向新位置（如 HD-3 把 README 改为指向本说明文件）。
- 若目标文件**已废弃** → 删除该链接（保留同行其余内容）。
**执行**：把失效链接改写为正确的绝对路径 `file:///<<子记忆文件目录绝对路径>>/<目标文件名>`；若体系内已无对应文件，则删除该链接、保留同行其余内容。
**验证**：`check` 该条维度3 错误消失；再跑 `断链检测.py` 确认 P-1 越界为 0。

### 7.2 修复错链（锚点 `#xxx` 不存在）

**识别**：`check` 维度4 报告 `[维度4] 锚点不存在`。
**执行**：按 §3 约定 3（锚点格式 · GFM）重算目标标题的锚点（全小写、空格→`-`、去特殊字符），改正链接中的 `#anchor`。
**验证**：`check` 维度4 该条消失；或用 `断链检测.py` 复扫锚点。

### 7.3 迁移错放内容（归属错误 / 单一事源违反）

**识别**：`validate` 纪律2 警告"疑似重复内容"；或人工发现同一规则出现在两个文件；或某内容语义更应归属另一子文件。
**决策**：确定"权威文件"（唯一事源）与"错放文件"。
**执行**：
1. 用 `get-offset` 定位错放章节行号，`Read(offset,limit)` 精准读取。
2. 将内容**剪切**到正确子文件的合适位置（新增 `##N`/`###N.X` 或并入现有章节）。
3. 在**原位置**保留一条**单向链接**指向新位置（不重复内容）。
4. 编号重排：**先按 §3.4 裁决路径，再执行**——步骤 2 若是**追加**到目标文件末尾（不引起既有编号位移）→ 走**路径 A**：手工给出正确编号，**只跑** `index`，**禁止** `rewrite`；若插在文件中部、引起后续编号连锁位移 → 走**路径 B**：`rewrite --dry-run` 预览 → `rewrite`（自动同步跨文件锚点 + 重建索引），并**逐章核验正文完整性**（§3.4 ③ 第 4 项）。**不得**不裁决就直接跑 `rewrite`。
5. 索引同步：`index`。
**验证**：路径 A → `check` + `断链检测.py` + 逐章 `grep -nP "^#{2,3} "` 核验；路径 B → 同上，另加 `validate` 纪律2 无新警告。`get-offset` 新位置可定位。

> 示例：若"UV 管理 Python"同时出现在两个子文件，保留 `Memory-全局禁令与环境约束.md ## 3.3` 为权威，另一处改为 `[详见 ## 3.3](file:///...#33-uv-管理-python...)` 单向链接。

### 7.4 修复主索引错误引用（如 HD-4）

**识别**：主索引"章节位置"列写了不存在的 `##N-M`（如 `## 3-99`）。
**执行**（**禁止手工编辑主索引区**，见 §3 约定 6 —— 该区由工具整区重建，手改必被覆盖）：
1. 先核对该子文件的真实 H2：`grep -oP '^## \d+-\d+.*' <子文件>`；
2. 若主索引与真实标题不符 → **跑 `index` 重建**；重建后仍不符 → 核对子文件 YAML 的 `file_number` 与标题编号（跑 `check` 维度11，按 §3.2 ③ 流程处理）；
3. 若"非编号文件"条目指向错误 → 按 §7.6 修正其四要素，再跑 `index`。
**验证**：`get-offset --file "Memory-入口能力与图谱.md" --section "## 5-4"` 可定位即正确。

### 7.5 编号 / 索引失同步

> **前置裁决（先分流）**：若失同步的起因是**向既有子文件插章**、且插入未引起既有编号位移，
> 应改走 **§3.4 路径 A**（手工正确编号 + 只跑 `index`，**禁止** `rewrite`），**不得**执行下列一键复位——
> `rewrite` 在该结构下会编号碰撞并**静默丢弃整章正文**（§3.4 制定动因）。仅"改动既有编号 / 连锁位移"场景适用本流程。

**执行**（一键复位）：
```
uv run ... memory-mgr.py --no-interactive rewrite --dry-run   # 预览新编号与锚点映射
uv run ... memory-mgr.py --no-interactive rewrite             # 执行（同步锚点+索引）
uv run ... memory-mgr.py --no-interactive index               # 重建索引（已含于 rewrite，可再跑确保）
uv run ... memory-mgr.py --no-interactive sync                # 同步状态文件
uv run ... memory-mgr.py --no-interactive check               # 验收：14 维度（含维度11 编号完整性）
uv run ... python 断链检测.py                                  # 验收：锚点唯一性 + 链接可达性
uv run ... memory-mgr.py --no-interactive verify              # 等价：上述五项一键跑完并出汇总表
```
> `rewrite` 按各子文件 YAML 的 `file_number` 确定文件顺序（**零硬编码文件名**），生成 `N-M-X-Z` 编号，并自动同步跨文件与同文件锚点。规范见 §2.3，保障制度见 §3.2。**收尾须人工在编辑器中抽样点击 ≥3 条锚点链接**（§3.2 ②-4）。

### 7.6 新增 / 删除子文件

> **决策前置（不可跳过）**：`add` 之前必须先完成 §3.1 归属判定——仅当"第 3 步三门槛同时满足 + 四要素已定义"时才可新建；判定不唯一时按 §3.1 第 4 步暂停并询问用户。**禁止**由"想新建"直接跳到命令。

**新增（新建子文件）**：
1. **素材规范化**（把外部素材转为合规正文；缺此步会产出不合规结构，见 §6 D-11）：
   - ① 去掉素材的文档标题 H1；**若素材含"第X篇"类篇标题，一并删除**（v5.0.0 起体系不再使用篇标题）；
   - ② 素材的 `##` **可保持无编号状态**——编号由工具生成：`add` 分配 `file_number` 后，`rewrite` 按 `## N-M` 自动补号（规范见 §2.3）。**禁止手工编号**。**例外**：本条规制的是**新建子文件**场景；向**既有**子文件插章时的手工编号按 **§3.4 路径 A** 执行（两者场景不同，不冲突，冲突时以 §3.4 为准）；
   - ③ 逐条比对 §2.2 与既有章节，确认无同一事源的重复定义（有则改为单行引用）。
2. **预览**：`uv run ... memory-mgr.py add --topic "主题名" --content "<规范化后的文件路径>" --dry-run`
   （在预览输出中确认将分配的 `file_number` = 当前最大 N + 1）
3. **执行**：`uv run ... memory-mgr.py add --topic "主题名" --content "<规范化后的文件路径>" --positioning "..." --role "..." --theme "..." --scope-in "..." --scope-out "..."`
   （自动分配 `file_number`、补 tags 与子→主回链、生成编号、重建索引与写前路由卡、跑 `check`；四要素参数缺失时会打印 WARN）
4. **字段落库**：四要素 + `file_number` 经命令自动写入新文件 YAML（四要素也可事后直接改该文件 YAML）。
   **无需**手工回写本手册 §2.1 或主文件——`index` 已把新子文件自动并入主文件写前路由卡。
5. **验收**：`check` 维度 11 / 维度 12 无 ERROR + `断链检测.py` 锚点唯一性无告警（§3.2 ②-3）。

**删除**：
```
uv run ... memory-mgr.py remove --file "Memory-x.md" --force --dry-run   # 预览受影响引用
uv run ... memory-mgr.py remove --file "Memory-x.md" --force             # 执行（.bak 备份+清引用+重编号+check）
```
> 非交互预览**必须配 `--force`**：`remove --dry-run` 单用仍会弹出 `确认删除 X？(y/N)` 并抛 `EOFError`（§6 D-10）。`add` 只写新文件，不需要 `--force`。
> 删除前务必核对 `--dry-run` 列出的引用清单。

**验证**：`validate` 三项全通过（链接 / 索引一致性 / 12 条纪律）；`check` 维度 11（编号完整性）/ 维度 12（清单一致性）无 ERROR；`断链检测.py` 断链 0、P-1 越界 0、P-2 回链齐全、锚点唯一性无告警；**人工在编辑器抽样点击 ≥3 条锚点链接确认可跳转**（§3.2 ②-4）。

### 7.7 YAML 字段缺失

**识别**：
- 缺 8 项基础字段 → `check` 维度8 / `validate` 纪律6 警告「缺必填字段」；
- 缺四要素字段 → `check` 维度10 警告「缺少四要素字段」，同时主文件路由卡对应单元格显示 `[待补]`。

**执行**：
- 8 项基础字段：在对应子文件 YAML Front Matter 补 `title/topic/tags/related/scope/created/updated/parent`（见 §3 约定5）；
- 四要素字段：按 §2.2 ①「字段规范」补齐 `positioning` / `role` / `theme` / `scope_in` / `scope_out`，**只改该子文件 YAML**（改后跑 `index`，主文件路由卡自动更新）。

**验证**：`check` 维度8 + 维度10 均无警告；`validate` 纪律6 通过、附加校验无新增提示。

### 7.8 跨机器 / 换目录移植（占位符代入 SOP）

**何时触发**：主记忆文件路径或子记忆文件目录发生机器 / 路径变更时，按本 SOP 代入真实路径后再执行任何维护。

**事实源**：用户告知（优先）或按 §0.1 用 `ls` 发现并请用户确认的 **P = 主记忆文件绝对路径**、**D = 子记忆文件目录绝对路径**（D 内含子文件 / 本手册 / 维护工具 / 状态文件）。

**步骤**：
0. 取得 P、D 作为唯一事实源；不直接复用旧手册 / 旧状态文件里的路径。
1. 重写 `memory-state.json` 的 `paths` 对象：`main_file=P`、`sub_files_dir=D`、`state_file=D/memory-state.json`（注意 `sync` 不重写该对象，须手工或一次性脚本改；改前先备份）。
2. 将本手册占位符代入真实值：`<<主记忆文件绝对路径>>` → P，`<<子记忆文件目录绝对路径>>` → D（手册同时用了 `\` 与 `/`，两种分隔符都覆盖）。
3. 重写子文件 `.md` 内部链接（回链主文件 + 互链 + 手册链）：跑 `check` 维度3 + `断链检测.py` 列断链 → 按 §7.1 改指向新绝对路径（§0.1 先 `ls` 核验、§0.2 严禁 `check --fix` 盲删）。
4. 验收：跑 §5 审计（`check` + `断链检测.py` + `validate`）三项全绿；人工在编辑器抽样点击 ≥3 条锚点确认可跳转（§3.2 ②-4）。
5. 收尾：删除迁移前备份（如 `memory-state.json.bak-*`）；在 §11 变更日志记录本次移植。

**关键陷阱**：① 分隔符双轨（手册同时用 `\` 与 `/`）必须两种都覆盖；② 必须先完成步骤2（手册代入）再做步骤3，否则 Agent 仍读旧路径自我指涉；③ **环境变量须区分两种形态**：**命令行**里的 `%USERPROFILE%` / `$HOME` 由 shell 展开而非 Python 展开，作为 `python xxx.py --main-file %USERPROFILE%\...` 这类**字面**传入时**不**被展开，不可依赖；但工具**内部**用 `os.path.expanduser('~')` 读取用户目录（v5.3.0 起主文件默认值即由此推导），以及 `MEMORY_MAIN_FILE` / `MEMORY_SUB_FILES_DIR` 两个环境变量由工具**自行**读入并展开，二者均**可依赖**；④ 状态文件 `paths` 是 `sync` 盲区，必须手工 / 脚本改。

> **v5.3.0 移植简化**：因主文件默认值已改为 `<用户目录>/.workbuddy/MEMORY.md`、子目录默认值改为脚本同目录，**换机后多数场景无需任何代入**——把整个 `Memory-Data` 目录复制到新机、主文件置于新用户目录的 `.workbuddy/` 下即可自动生效。仅当实际布局与默认规则不符（如主文件另置）时，才需按上述步骤代入，或直接传 `--main-file` / `--sub-files-dir`。

## 8. 安全边界（红线）

| 红线 | 说明 |
|------|------|
| **禁止引用 / 链接体系外文件** | 主文件与任一子记忆文件中，**禁止**出现指向体系外目录或文件的链接。合法链接目标**仅有三类**：子记忆文件 `Memory-*.md`、本手册 `WorkBuddy记忆文件说明.md`、主文件 `MEMORY.md`（即 `断链检测.py` P-1 的 `ALLOWED_TARGETS` 白名单）。凡指向 `Memory-Data` 目录内**非** `Memory-*.md` 的文件（如 `task-methodology\` 下的过程文档、`.py` 脚本、`.json` 状态文件）或体系外任何路径者，一律判**越界**，须删除。此为 `check` 的盲区（§6 D-8），只能靠 `断链检测.py` P-1 与 §5 步骤4 人工核对拦截。 |
| **禁止盲 `check --fix`** | `check --fix` 会按"断链"自动删除链接（HD-1 / HD-2 历史误报虽已修复 v4.2.0，但任何工具输出仍可能含边缘误判）→ 破坏系统。纠偏必须人工逐条确认（§7），严禁无人工核对即执行 `--fix`。 |
| **改前备份** | 工具自动 `.bak`；人工改也先复制原文件。 |
| **`--dry-run` 预览** | `add`/`remove`/`rewrite` 先预览再执行。 |
| **破坏性需 `--force`** | `remove`/`restore` 非 `--force` 仅警告退出。 |
| **存在性优先于删除** | 任何"删除/修复"前先 `ls` 确认目标真实状态，不凭工具输出。 |
| **meta scope 直改** | 本目录与主文件可在主工作树直接改，不需 worktree（本地维护）。**v5.3.0 起两个 `.py` 已纳入 git 跟踪**，须按仓库纪律提交，不得再以"不受跟踪"为由跳过提交。 |
| **主文件工具写入区禁改** | 主文件 `ROUTE_CARD` / `MAIN_INDEX` 两区由工具整区重建，手工编辑会被覆盖；须改数据源（子文件 YAML 四要素）或走 §7 工具流程。 |
| **编号禁手工改** | 章节编号（`## N-M` / `### N-M-X` / `#### N-M-X-Z`）与 `file_number` 一律由工具生成（`number` / `add` / `rewrite`）。**改动既有编号**会导致编号与 `file_number` 不一致、锚点失同步，并违反 §2.3 ④ 的唯一性要求。**例外**：§3.4 路径 A 下为**新增**章节手工编号（不改动任何既有编号）是允许且必须的。 |
| **插章禁 `rewrite`（路径 A，见 §3.4）** | 向子记忆文件**追加**章 / 节、且不引起既有编号位移时，**禁止**运行 `rewrite`——其在「已存在 N-M 含子节 + 新 N-(M+1) 含子节」结构下会编号碰撞并**静默丢弃整章正文**，且 `check` 全绿不报警。**仅当**插入位置引起编号连锁位移时，才走路径 B（`rewrite` + 逐章核验正文完整性）。 |
| **主文件不承载明细（见 §0.15）** | 主文件只保留「高频纪律速览 + 两个工具写入区（表① / 表②）+ 必要的全局指向」三类内容；其余一律下沉子记忆文件。凡新增内容先按 §3.1 判定归属，命中子文件即写入子文件，防止主文件膨胀导致检索效率下降与记忆稀释。 |
| **编号分隔符禁用点号** | 编号必须用连字符 `-`（如 `## 3-10`），**禁止**点号形态（如 `## 3.10`）——点号会被 GFM 锚点规则删除，造成「工具校验通过、编辑器点击不跳」的假通过（详见 §2.3 ③）。 |
| **不碰大文件全量** | `Memory-GitHub全流程操作.md` 超千行，用 `get-offset`+`Read(offset,limit)` 精准读，不全量灌入上下文。 |

## 10. 记忆文件格式强制要求

> **适用范围（强制）**：修改、维护**主记忆文件 `MEMORY.md` 与任一子记忆文件 `Memory-*.md`** 时必须遵循；本手册自身的内容组织同样适用。违反任一条即判定为格式不合规，按 §7 纠偏。
> **本节定位**：本节是"记忆文件格式强制要求"在本文件内的**唯一权威定义处**（依第 7 条单一事源），他处只能引用本节条目编号（如"依 §10 第 4 条"），**不得重述**。

| # | 要求 | 判定标准（可执行） |
|---|------|------------------|
| 1 | **格式保真与标题适配** | 保持目标文件 Markdown / TXT 形态与整体风格不变。**当且仅当**原标题与其所辖内容不匹配时，须改写该标题使之与内容严格匹配、适用；内容与标题已匹配则标题**保持原样**。仅调整标题、内容排序与引用关系，不改变文件基本格式。 |
| 2 | **层级递进** | 内容须分多级标题（`#`→`##`→`###`→`####`），父包子、子细化父；**不得平铺**，**不得靠缩进伪装层级**。 |
| 3 | **层级标记（标准 Markdown 语法）** | 一律用 `#` / `##` / `###` / `####` 标准标题语法划分层级；**禁止**用缩进、空行、手动编号等非标题手段伪装层级结构。 |
| 4 | **序号连续唯一** | 各层级序号**在本文件内连续且唯一**（子记忆文件用 `## N-M` / `### N-M-X` / `#### N-M-X-Z`，规范见 §2.3；N = 文件编号，**不跨文件连续**；主文件用其自身编号体系）；**不得**重号、跳号、缺号。 |
| 5 | **强相关相邻与线性排序** | 同类、同流程、因果链上的章节，须按**前后工序顺序紧挨排列**并实现线性排序；禁止循环排序。**唯一例外**：工序本身即为循环迭代（如「代码审计 ↔ BUG 修复」）时允许循环排序，且须在该处**显式标注「必要循环」**。 |
| 6 | **常用前置** | 高频内容、工作流置于文件**靠前位置**（文首设速查索引），实现高效检索与调用。 |
| 7 | **单一事源** | 任一事实源 / 事项 / 要求 / 流程 / 操作，**仅在一处权威定义**；他处只能引用，**不得重述**。 |
| 8 | **无重复矛盾** | **不得**出现重复或相互矛盾的叙述。 |
| 9 | **无歧义 + 具名禁用词** | 措辞唯一可执行，**不得**有歧义或多解；凡需条件判断处须给出明确的**是非标准或阈值**，**不得**用留有余地的说法替代。**具名禁用词（在强制条款中出现即违规）**：视情况、一般、通常、酌情、尽量、尽可能、适当、必要时、原则上、建议。 |
| 10 | **引用单向且后序引用前序（导航豁免）** | 引用只能单向；只允许「**后序（晚出现）章节 引用 前序（早出现）章节**」；**禁止**前序引用后序（前向引用）。**唯一豁免**：**导航型前向引用**——速查索引表 / 映射表，以及"见 §X"类章节指引，其本质是指引读者从"适用场景"跳到"对应章节"，须确认被引章号 > 引用章号（真前向）且目标精准唯一；除该豁免外**严禁**任何反向 / 前向引用。 |
| 11 | **禁止无必要循环引用 / 调用（必要循环豁免；主↔子豁免）** | 严禁无必要的循环引用 / 调用（A→B 且 B→A）；**必要的循环引用 / 调用不在此列**——例如循环迭代的「代码审计工序」与「BUG 修复工序」因工序本身需反复迭代而互为前后，此类必要闭环允许存在，且整体豁免第 10 条的前向引用限制。**主记忆文件与子记忆文件之间的双向 / 循环引用（主→子索引、子→主回链）为本体系设计中枢，明确豁免**（见 §0.4）。除此之外**严禁**任何反向 / 前向引用。 |
| 12 | **引用精准唯一且格式一致** | 引用须精准、明确、唯一，指到可在正文**精确命中**的具体标题；**不得**"详见相关章节"式模糊指向。跨章节引用格式基准：以反引号包裹、含**完整标题前缀**的节级标题（如 `### 12.3 阶段 2 整改`）；当目标文件含速查索引表 / 映射表时，全文跨章节引用格式须与索引表**第二列逐字一致**，**禁止**裸编号（`12.3`）或"章标题 + 裸节号"形态。同节内引用具名条目（如列表项「阶段 2」）不受上述格式基准约束，但须保证该具名在全文唯一。 |
| 13 | **文件内 vs 跨文件** | 第 10、11 条的引用方向约束**仅作用于同一文件内部**；跨文件引用（子文件之间、主文件与子文件之间、文档之间）**不受方向约束**，但须满足第 12 条的精准唯一。 |
| 14 | **第 7 条作用域（本文件内）** | 同一事实源 / 事项 / 要求 / 流程 / 操作，在**本文件内**只允许一处权威定义，他处只能引用、**禁止重述**。**本节（§10）即本文件内"记忆文件格式强制要求"的唯一定义处。** |
