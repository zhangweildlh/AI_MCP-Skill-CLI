# 引导词（调用范式）

> 本文件沉淀 `wechat-article-to-ima` 的标准调用范式（引导词）。四套引导词与 `state.js` / `pipeline.js` 的代码契约严格对齐：
> - 引导词 **A / B / C** 分别针对卡片 A / B / C 做**全量采集**（首跑 / 周期全搜），三者**平行关系**——各命令强制 `--card`，进度文件按卡隔离，互不污染。
> - 引导词 **续跑守护** 针对 A / B / C 做**断点续跑**：侦测到某卡未完整执行时，对该卡续跑，目标让三卡全部完整执行。
>
> 通用铁律（缺 `--card` 的命令会被 `state.js` / `pipeline.js` 直接拒绝，故平行关系由代码强制）：
> - 检索在技能外部 `wechat-article-search` 完成，逐词生成 `[WS]/[关键词].json`；入库由 `pipeline.js --search` 处理。
> - 进度文件 `[WS]/_progress.json` 的任何写操作一律经 `state.js`（F9 唯一入口）。
> - 隔离区 `failed_quarantine/` 按卡加前缀（`safeFile(card)+'__'`），每卡独立跑、必带 `--card`。

---

## 引导词 A —— 卡片 A 全量采集（首跑 / 周期全搜）

前置：`[WS]`=工作区根目录，`[KB]`=知识库 ID，A 卡 `folder_id=folder_7511772189689986`。

A 卡全量关键词（主词簇 + 变体词簇，逐一全搜 = 全量）：

- 主词簇：工程总承包、EPC、总包
- 变体词簇：总承包EPC、EPC总承包

```
0. 依赖核查（必须 --json，退出码 0 才继续）：
   node scripts/check-deps.js --json

1. 进度文件就绪：若 [WS]/_progress.json 不存在按模板创建；损坏则重建（各卡 lastRun 置空、rotateIndex=0）。

2. 取 A 卡全量关键词（主词簇 + 变体词簇，逐一全搜 = 全量；不传 --rotate-index，两簇都搜）。

3-5. 对每个关键词（主词簇 → 变体词簇逐一）循环执行：
   3. 两段式检索（先取 Cookie → 判 rc==0 → 再检索，禁止 && 串联），落 [WS]/[关键词].json，间隔 cool_down。
   4. 逐结果入库（必带 --card A 与 --workspace；进度文件由 pipeline 经 state.js 唯一入口写回）：
      node scripts/pipeline.js --workspace "[WS]" --card A --search "[WS]/[关键词].json" --kb-id "[KB]" --folder-id "folder_7511772189689986"
   5. 每完成一词，立即累计（累积并集、去重，供续跑 diff-keywords 取差集）：
      node scripts/state.js --progress "[WS]/_progress.json" update-card --card A --searched-keywords "[该关键词]"

4b. 全部关键词搜完入库后，补入本卡历史失败残留（按卡隔离，消费 [WS]/failed_quarantine/A__*.md，不重搜）：
   node scripts/pipeline.js --workspace "[WS]" --card A --ingest-quarantine --kb-id "[KB]" --folder-id "folder_7511772189689986"
   （他卡残留自动跳过；闸门未过的质量失败篇目自动跳过，仅重入「闸门过但入库失败」篇目）

6. 复验（KB 复核模式，禁止手工拼凑四栏）：
   node scripts/state.js --progress "[WS]/_progress.json" report --kb-id "[KB]" --folder-id "folder_7511772189689986"

7. 收尾清扫：pipeline 已自动将未入库篇目写入 [WS]/failed_quarantine/<card>__<title>.md（带卡前缀，步骤 4b 会续跑消费），
   本步仅删除检索中间文件（[WS]/[关键词].json、_process_summary.json 等）；并核对无游离 .md
   （若有非卡前缀的游离 .md，按归属卡改名后移入 failed_quarantine/ 供续跑守护补入）。

8. 轮转收尾（state.js 唯一入口）：
   node scripts/state.js --progress "[WS]/_progress.json" update-card --card A --last-run [今天] --next-due [今天+cycle_days] --rotate-index 0 --status completed
```

## 引导词 B —— 卡片 B 全量采集（首跑 / 周期全搜）

前置：`[WS]`=工作区根目录，`[KB]`=知识库 ID，B 卡 `folder_id=folder_7512040100861636`。

B 卡全量关键词（主词簇 + 变体词簇，逐一全搜 = 全量）：

- 主词簇：城市更新、一老一小、小区改造、城中村改造、街区改造、社区改造、城市合伙人、智慧城市、海绵城市、基础设施改造
- 变体词簇：有机更新、微更新、城市双修、小区整治、城中村更新、街区整治、街区打造、社区整治、社区打造、基础设施更新

结构与引导词 A 完全一致，仅替换 `--card B` 与 B 卡 `folder_id`，并补充重跑说明：

```
0. node scripts/check-deps.js --json
1. 进度文件就绪（不存在创建 / 损坏重建）。
2. 取 B 卡全量关键词（主词簇 + 变体词簇逐一全搜）。
3-5. 对每个关键词循环：
   3. 两段式检索 → [WS]/[关键词].json（间隔 cool_down）
   4. node scripts/pipeline.js --workspace "[WS]" --card B --search "[WS]/[关键词].json" --kb-id "[KB]" --folder-id "folder_7512040100861636"
   5. node scripts/state.js --progress "[WS]/_progress.json" update-card --card B --searched-keywords "[该关键词]"
4b. node scripts/pipeline.js --workspace "[WS]" --card B --ingest-quarantine --kb-id "[KB]" --folder-id "folder_7512040100861636"
6. node scripts/state.js --progress "[WS]/_progress.json" report --kb-id "[KB]" --folder-id "folder_7512040100861636"
7. 收尾清扫（删除中间 .json；核对无游离 .md）。
8. node scripts/state.js --progress "[WS]/_progress.json" update-card --card B --last-run [今天] --next-due [今天+cycle_days] --rotate-index 0 --status completed
```

**关键差异（重跑 vs 续跑）：**

- 若 B 需「从头强制全量重搜」：先执行
  `node scripts/state.js --progress "[WS]/_progress.json" reset-card --card B`
  现 `reset-card` 会清空本卡 `searchedKeywords=[]` 与 `failureClass=''`（**仅清 B、不动 A/C**），
  故后续 `diff-keywords` 返回完整词集 → 不会被旧差集误导、不会被旧 permanent 锁阻断。
- 普通周期续跑**不要 reset**，直接走上面第 2~8 步（`searched-keywords` 累积并集生效，续跑守护用 `diff-keywords` 取剩余词）。

## 引导词 C —— 卡片 C 全量采集（首跑 / 周期全搜）

前置：`[WS]`=工作区根目录，`[KB]`=知识库 ID，C 卡 `folder_id=folder_7512041610809167`。

C 卡全量关键词（主词簇 + 变体词簇，逐一全搜 = 全量）：

- 主词簇：全域土地综合整治、拆旧复垦、人居环境整治、千万工程、城乡融合发展、宜居宜业和美乡村、生态修复、耕地碎片化治理、智慧农业、智慧农田、山水林田湖草沙一体化、撂荒地治理
- 变体词簇：全域整治、生态保护修复

结构与引导词 A 完全一致，仅替换 `--card C` 与 C 卡 `folder_id`，并补充隔离区要点：

```
0. node scripts/check-deps.js --json
1. 进度文件就绪（不存在创建 / 损坏重建）。
2. 取 C 卡全量关键词（主词簇 + 变体词簇逐一全搜）。
3-5. 对每个关键词循环：
   3. 两段式检索 → [WS]/[关键词].json（间隔 cool_down）
   4. node scripts/pipeline.js --workspace "[WS]" --card C --search "[WS]/[关键词].json" --kb-id "[KB]" --folder-id "folder_7512041610809167"
   5. node scripts/state.js --progress "[WS]/_progress.json" update-card --card C --searched-keywords "[该关键词]"
4b. node scripts/pipeline.js --workspace "[WS]" --card C --ingest-quarantine --kb-id "[KB]" --folder-id "folder_7512041610809167"
6. node scripts/state.js --progress "[WS]/_progress.json" report --kb-id "[KB]" --folder-id "folder_7512041610809167"
7. 收尾清扫（删除中间 .json；核对无游离 .md）。
8. node scripts/state.js --progress "[WS]/_progress.json" update-card --card C --last-run [今天] --next-due [今天+cycle_days] --rotate-index 0 --status completed
```

**重点（隔离区按卡隔离）：**

- 隔离区 `failed_quarantine/` 现按卡加前缀（`safeFile(card)+'__'`），C 卡残留**不会**误入 A/B；但仍须「每卡独立跑、必带 `--card`」：
  `node scripts/pipeline.js --workspace "[WS]" --card C --ingest-quarantine --kb-id "[KB]" --folder-id "folder_7512041610809167"`
- **严禁不带 `--card` 跑 `ingest-quarantine`**（无 `--card` 时旧逻辑无法判定归属，会误食他卡残留）。

## 引导词 续跑守护 —— 对 A/B/C 断点续跑

前置：`[WS]`=工作区，`[KB]`=知识库 ID。**逐卡（A → B → C）执行**；目标让三卡全部完整执行。

```
1. 判定该卡是否需要续跑（满足任一即进入续跑）：
   - failureClass=permanent（interrupted）→ 停止续跑本卡，提示人工处理凭据（不得反复重试）；
   - 或 status ∈ {partial, pending, antispider_partial, limited}；
   - 或 state.js diff-keywords --card [卡] --keywords "[该卡全量关键词]" 返回非空（仍有未搜词）；
   - 或 [WS]/failed_quarantine/[卡]__*.md 存在残留（历史入库失败待补入）。
   （判定不依赖单一 status：搜索已完成但入库失败残留的场景，仅靠 status 会漏判，须结合差集与隔离区残差。）

2. 取剩余词（仅搜差集，避免重触发限流）：
   node scripts/state.js --progress "[WS]/_progress.json" diff-keywords --card [卡] --keywords "[该卡全量关键词（取自任务卡配置表：主词簇+变体词簇）]"

3. 对剩余词检索 → pipeline --search（同引导词 A 第 4 步，必带 --card + --workspace + --kb-id + --folder-id）：
   node scripts/pipeline.js --workspace "[WS]" --card [卡] --search "[WS]/[剩余词].json" --kb-id "[KB]" --folder-id "[该卡 folder]"
   每搜完一词，立即累计：node scripts/state.js --progress "[WS]/_progress.json" update-card --card [卡] --searched-keywords "[该关键词]"
   （否则下次 diff-keywords 仍含该词，导致重复搜索 / 重触发限流）

4. 补入本卡历史失败残留（按卡隔离，消费 failed_quarantine/[卡]__*.md）：
   node scripts/pipeline.js --workspace "[WS]" --card [卡] --ingest-quarantine --kb-id "[KB]" --folder-id "[该卡 folder]"
   （他卡残留自动跳过；闸门未过的质量失败篇目自动跳过，仅重入「闸门过但入库失败」篇目）

5. 失败分类可用：node scripts/state.js classify-failure --reason "..."（transient / permanent 决策）。

6. 收尾：node scripts/state.js --progress "[WS]/_progress.json" update-card --card [卡] --status completed
   （仍有剩余词或隔离残留则维持 partial）。
```
