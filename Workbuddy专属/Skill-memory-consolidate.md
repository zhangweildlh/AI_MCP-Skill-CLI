# 记忆整合（memory-consolidate）

## 一、定位

把 WorkBuddy 记忆体系中**分散、短期、碎片**的记忆，转化为**结构化、长期、可跨会话/跨 Agent 复用**的单一事实源；并在对**含速查索引表与跨章节引用的可写记忆文件**做整理/蒸馏/重写时，强制进行**交叉引用合规核查**，使产出文件达到「引用精准、唯一、格式一致、导航可达」的硬标准。本技能遵循设计契约：**零硬编码、零项目专属、跨 Agent 可移植、严格跨项目隔离**，由周期自动化驱动。

## 附：可选输入源耦合（task-methodology-consolidation 接入 · 用户授权硬编码例外）

> **用户授权例外**：本块为与 `task-methodology-consolidation` 技能衔接的**可选**输入源，系用户于 2026-08-09 显式授权之**唯一**硬编码例外；本技能其余所有路径仍严格遵循「零硬编码」原则（经 `$WORKBUDDY_CONFIG_DIR` 变量化）。

激活本技能（尤其由周期自动化驱动做记忆整合）时，额外将下列固定目录的产物作为输入源纳入蒸馏：

- **固定目录（用户指定硬编码点）**：`D:\Documents\AI_MCP-Skill-CLI\Memory-Data\task-methodology\`
- **匹配文件**：仅 `p2-` 前缀的过程态经验 MD（通用可移植类；`p1-` 项目专项产物不进跨项目下游，其去处与用途由用户自行决定）。命名规则见 `task-methodology-consolidation` 第八节。
- **纳入范围**：`p2-` 文件跨项目通用，全量纳入本次蒸馏候选，不按文件头 `关联路径` 字段过滤当前 workspace（P2 本身无项目边界）。
- **容错**：若固定目录不存在或无 `p2-` 文件，静默跳过，不影响本技能既有记忆整合流程。
- **不写回**：本技能只读取并蒸馏这些经验，不修改、不删除该目录下的文件。
- **来源定位**：本 Skill 产物仅为输入源之一、非唯一；本技能另有 `MEMORY.md`、每日日志、会话记忆等多元输入源。

## 二、设计原则（强约束，不可违背）

1. **零硬编码（唯一例外见『可选输入源耦合』节）**：所有路径通过环境变量/约定解析，绝不写死绝对路径、用户名、项目名。默认根目录为 `$WORKBUDDY_CONFIG_DIR`（未设置时回退 `~/.workbuddy`）。**唯一例外**：与 `task-methodology-consolidation` 衔接的固定产物目录 `D:\Documents\AI_MCP-Skill-CLI\Memory-Data\task-methodology\` 为用户 2026-08-09 显式授权硬编码，仅限于「可选输入源耦合」节作为接入点，不构成对零硬编码原则的一般性突破。
2. **零项目专属**：技能逻辑与任何具体项目无关，可放入任意用户级 `skills/` 目录直接使用。
3. **跨 Agent 可移植**：指令自包含，不依赖特定 Agent 的私有能力；仅使用通用工具（Read / Write / Edit / Grep / Bash）。
4. **严格跨项目隔离**：仅操作记忆目录（全局与各 workspace 的 `memory/`），绝不触碰项目源码、文档与配置；不同 workspace 的记忆互不串扰。
5. **职责边界（对照 MiMo `/dream` ↔ `/distill`）**：本技能对应 MiMo `/dream`（Memory Consolidation），**仅做记忆整合/巩固**；将重复工作流提炼为 skill / subagent / command 是 MiMo `/distill` 的职责（本机有对应的 skill 蒸馏技能承担）。本技能**不创建、不打包、不修改任何 skill / 命令 / 子代理**，仅可在发现候选时以一行指针提示交由对应的 skill 蒸馏技能处理。
6. **信任但验证**：任何脚本化核查产出的「0 残留 / 0 缺失 / 全通过」结论，均须另起独立脚本重新扫描目标文件交叉印证；脚本自身可能有缺陷，禁止把单次脚本输出当作最终结论交付。

## 三、路径约定（全部变量化）

- 全局长期记忆：`$WORKBUDDY_CONFIG_DIR/MEMORY.md`
- 全局每日日志：`$WORKBUDDY_CONFIG_DIR/memory/YYYY-MM-DD.md`（append-only）
- 全局会话记忆：`$WORKBUDDY_CONFIG_DIR/memory/<uuid>_memory.md`
- 项目级记忆：`<workspace>/.workbuddy/memory/`（结构同上）

## 四、执行工作流

1. **盘点**：列出所有记忆源（全局 + 各 workspace），统计每日日志的时间跨度与体量。
2. **过期判定**：阈值**参数化**，默认 `threshold_days = 30`（贴合 WorkBuddy 自身记忆维护约定）；可按需覆盖为 MiMo 原版 `/dream` 的 **7 天**。早于阈值的每日日志进入「待蒸馏」集合。
3. **蒸馏合并**：将待蒸馏日志按主题归类，提取**长期有效**的事实（用户偏好、跨项目约定、稳定结论、已验证的方案），写入/更新 `MEMORY.md` 对应章节；剔除一次性、临时、已失效的内容。**若 `MEMORY.md` 含速查索引表或跨章节引用，合并后必须触发本文件「交叉引用合规核查专项」**。
4. **去重与结构化**：合并重复条目，保持 `MEMORY.md` 主题清晰、体量可控（单主题须控制在 3000 字以内，全文须控制在 8000 字以内）。
5. **清理（需确认）**：对已完整蒸馏的过期每日日志，先备份再删除；删除前必须向用户列出清单并获得显式确认，**绝不静默删除**。
6. **备份**：任何对 `MEMORY.md` 或日志的修改前，先生成 `.bak` 副本（同名 + `.bak` 后缀）。

## 五、安全门禁

- 每日日志 append-only；会话记忆的 `RAW_JSON` 块不可被本技能自动改写。
- 删除类操作一律先备份 + 显式确认；清单、状态、风险须先行展示。
- 本技能只处理记忆文件，不执行任何分支、发布、网络或系统级破坏性动作。
- **交叉引用核查作用域限定**：核查仅作用于可写记忆文件（全局/项目级 `MEMORY.md`、规则文件、`SKILL.md`）；**每日日志为 append-only，仅作为被引用的证据读取，绝不被改写或纳入引用整改**。

## 六、自动化接入

可由周期自动化（automation）以「每日/每周」节奏调用，prompt 仅需描述「执行记忆整合」即可，无需携带路径或调度细节——路径与阈值均按本技能约定自动解析。若目标 `MEMORY.md` 含速查索引表，交叉引用核查专项将自动纳入执行。

## 七、产出验收

- `MEMORY.md` 更新后结构完整、无重复、事实仍有效；
- 被清理的日志均有 `.bak` 留存且经用户确认；
- 任何项目的 `memory/` 之外目录未被改动；
- **含速查索引表的 `MEMORY.md` 额外通过本文件「六连验证门禁」**（章号连续、索引精确唯一、裸编号残留 0、围栏偶数、导航全过、节级引用命中零悬空）。

### 8.1 12 条强制要求（本文件内嵌）

本技能在整理 / 整合 / 巩固「记忆」及蒸馏规则 / `SKILL` / `subagent` / `command` 时，必须使目标文件完全满足以下 12 条强制要求（本文件自包含，不引用外部 Skill）：

1. **格式保真与标题适配**：保持目标文件 Markdown 形态与整体风格不变；当且仅当原标题与其所辖内容不匹配时，须改写该标题使之与内容严格匹配、适用；内容与标题已匹配则标题保持原样。仅调整标题、内容排序与引用关系，不改变文件基本格式。
2. **层级递进**：内容须分多级标题（`#`→`##`→`###`→`####`），父包子、子细化父，不得平铺或靠缩进伪装层级。
3. **层级标记（符合 Markdown 语法）**：一律用 `#` `##` `###` `####` 等标准 Markdown 标题语法划分层级；禁止用缩进、空行、手动编号等非标题手段伪装层级结构。
4. **序号连续唯一**：各层级序号（第 N 章 / N.M / N.M.P）全局连续且唯一，不得重号、跳号、缺号。
5. **强相关相邻与线性排序**：同类、同流程、因果链上的章节，须按前后工序顺序紧挨排列并实现线性排序；禁止循环排序，唯一例外：工序本身即为循环迭代（如「代码审计 ↔ BUG 修复」）时允许循环排序，且须在该处显式标注「必要循环」。
6. **常用前置**：高频内容、工作流置于文件靠前位置（文首设速查索引），实现高效检索与调用。
7. **单一事源**：任一事实源 / 事项 / 要求 / 流程 / 操作，仅在一处权威定义；他处只能引用，不得重述。
8. **无重复矛盾**：不得出现重复或相互矛盾的叙述。
9. **无歧义**：措辞唯一可执行，不得有歧义或多解；凡需条件判断处须给出明确的是非标准或阈值，不得用留有余地的说法替代。具名禁用词（在强制条款中出现即违规）：视情况、一般、通常、酌情、尽量、尽可能、适当、必要时、原则上、建议。
10. **引用单向且后序引用前序（导航豁免）**：引用只能单向；只允许「后序（晚出现）章节 引用 前序（早出现）章节」；禁止前序引用后序（前向引用）。唯一豁免：速查索引表 / 映射表类前向引用合法——其本质是指引读者从「适用场景」跳到「对应章节」，须确认被引章号 > 引用章号（真前向）且目标精准唯一；除该豁免外仍严禁任何反向 / 前向引用。
11. **禁止无必要循环引用 / 调用（必要循环豁免）**：严禁无必要的循环引用 / 调用（A→B 且 B→A）；但必要的循环引用 / 调用不在此列——例如循环迭代的「代码审计工序」与「BUG 修复工序」因工序本身需反复迭代而互为前后，此类必要闭环允许存在，且整体豁免第 10 条的前向引用限制；除此之外仍严禁任何反向 / 前向引用。
12. **引用精准唯一且格式一致**：引用须精准、明确、唯一，指到可在正文精确命中的具体标题，不得「详见相关章节」式模糊指向。跨章节引用的格式基准：以反引号包裹、含完整标题前缀的节级标题（如 `` `### 12.3 阶段 2 整改` ``）；当目标文件含速查索引表 / 映射表时，全文跨章节引用格式须与索引表第二列逐字一致，禁止裸编号（`12.3`）或「章标题 + 裸节号」形态。同节内引用具名条目（如列表项「阶段 2」）不受上述格式基准约束，但须保证该具名在全文唯一。

## 九、交叉引用合规核查专项（六步·每步含「操作」与「禁令」）

> **触发时机**：本技能对含「速查索引表 / 映射表」与跨章节引用的可写记忆文件（全局/项目级 `MEMORY.md`、规则文件、`SKILL.md`）做整理/蒸馏/重写时，必须跑此专项。每日日志为 append-only，**不属此专项范围**（仅在被引用时作为证据读取，不被改写）。
>
> **四性达标标准**（专项验收的刚性目标）：
> - **精准性**：引用须精确到被引处真实标题文字；
> - **唯一性**：每个被引标题全文唯一存在、无悬空；
> - **一致性**：全文引用格式须与速查索引表第二列完全一致（反引号包裹、含完整前缀的节级标题）；
> - **可达性**：从索引表「你要做的」能精准唯一跳到「你要阅读/执行的」章节。

**步骤 1 — 双模式提取（防漏检）**
- **操作**：用脚本/手工同时提取两类锚点——① 章级：`## 第N章 <章标题>`；② 小节级：`### N.N <节标题>`（及 `#### N.N.N`）。建立「标题键 → 行号」正向索引，供后续匹配与导航测试使用。
- **禁令**：禁止只提取章级而漏掉小节级裸引用；禁止用 `\b` 边界（中文「章」非 `\w`，`\b` 在中文章节号后失效，会导致章级键全丢失）；禁止把路径版本号（`D:\...\3.14.5`）、命令行参数（`-m 1`）、URL（`//`）误判为引用。

**步骤 2 — 方向性审计（五类边）**
- **操作**：对每条引用构造有向边「源章节 → 目标锚点」，分类为 IDX（指向索引表）、SAME（章内自指）、BACK（后序引前序，合法）、FWD（前序引后序）、DANGLING（目标不存在）。统计每类数量并列出 DANGLING 清单。
- **禁令**：禁止保留正文叙述性的前向引用（FWD）；仅「速查索引表/映射表」类前向引用可豁免（导航豁免），且须确认被引章号 > 引用章号（真前向）；禁止出现 DANGLING（悬空）引用——所有引用目标必须存在且唯一。

**步骤 3 — 索引表两列匹配**
- **操作**：读取文件顶部「速查索引表」（应用场景 → 章节）。逐行核对：左列「你要做的」与右列「你要阅读/执行的」是否精准对应；右列必须是反引号包裹的**完整小节标题**（含 `### ` 前缀），如 `` `### 2.3 UV 管理 Python` ``。
- **禁令**：禁止右列用裸编号（`2.3`）或「章标题 + 裸节号」；禁止标题含内嵌反引号（如 `` `gh pr` ``）造成嵌套——须改用中文书名号《gh pr》或降为单反引号；禁止把表头行（「你要做的 → 你要阅读/执行的」）计入索引条目。

**步骤 4 — 残差扫描（双盲点）**
- **操作**：扫描正文所有「带引导动词（见/引用/详见/参见/参考/按）且未被反引号完整包裹」的引用，识别两类残留——A：裸章号/裸节号（`第N章`/`N.N` 裸露）；B：章标题已合规包裹但后缀节号裸露（`` `## 第16章 工作流四` 16.2 ``）。同时扫描反引号**内部**是否仍含「章标题 + 裸节号」（升级遗漏）。
- **禁令**：禁止仅凭历史脚本「0 残留」结论交付（实测历史 `check_residual` 漏检 28 处 B 类 + 6 处遗漏节号，必须独立重扫全文）；禁止把已反引号包裹的章标题内的节号当作合规（盲点 B 也须清零）；禁止用引导动词限定漏捕「或/、」前导的引用。

**步骤 5 — 格式升级为节级标题**
- **操作**：① 先建「节号 → 真实节标题」映射 MAP，核验 MAP 对全部涉及节号的覆盖率 = 100%（任一节号须能在正文精确命中 `### N.N 标题`）；② 将 A/B 两类残留统一改写为反引号包裹的**真实小节标题**（`` `### N.N 标题` ``），与索引表第二列逐字同格式；范围写法（`15.2–15.3`）须拆分为两条独立引用；③ 反引号**内部**残留的「章标题 + 裸节号」一并升级为节级标题。
- **禁令**：禁止交付「章标题 + 裸节号」形态；禁止 MAP 未 100% 覆盖就批量改写（缺失节号须先补全 MAP 或回查正文标题）；禁止用单正则两次 replace 导致二次匹配（须单正则单 replace 单向扫描，避免已插入反引号内二次匹配产生嵌套反引号）。

**步骤 6 — 导航可达性测试**
- **操作**：取「速查索引表」左列每一条「你要做的」需求，用其中 2~3 字连续子串在全文检索，验证能精准唯一命中右列对应的小节标题（存在且唯一）；另对正文升级后的全部 `` `### N.N 标题` `` 引用，逐字核对是否在正文精确命中真实节标题。
- **禁令**：禁止用空格/标点 `split` 切分中文连写需求（中文无词边界，会整串失配误报）；禁止接受「多命中」或「0 命中」作为通过（须唯一）。

## 十、六连验证门禁（硬指标·全 PASS 方可交付）

1. **章号连续**：所有 `## 第N章` 的 N 从 1 起连续无跳号/重号。
2. **索引精确唯一**：索引表每条右列在正文精确唯一命中，0 悬空。
3. **裸编号残留 = 0**：全文无任何未被反引号包裹的 `第N章`/`N.N`/`N.N.N` 引用（A、B 两类盲点均清零）。
4. **围栏偶数**：所有 ``` 代码围栏独占一行且成对（偶数），无奇偶失配致全文塌陷。
5. **导航全过**：索引表左列需求 100% 命中右列章节（精准唯一）。
6. **节级引用命中零悬空**：全文所有 `` `### N.N 标题` `` 类节级引用逐字精确命中正文真实节标题，0 悬空、0 歧义。

## 十一、避坑红线（十条·违反即整合失败）

1. **正则 `\b` 中文失效**——提取章级键禁用 `\b`，改用 `rest.match(/^第(\d+)章/)` 与 `rest.match(/^(\d+\.\d+)/)`。
2. **章标题是二级 `##` 而非一级 `#`**——提取正则须 `^#{2,4}\s+第(\d+)章`，禁只匹配 `^#\s+`。
3. **裸引用检测过宽**——排除路径版本号/命令行参数/URL/自然语言称呼（如「第1.2 二次授权铁律」是叙述非引用）。
4. **信任但验证**——任何「0 残留/0 缺失」结论须独立重扫全文复核，禁止轻信单次脚本输出。
5. **单正则单 replace**——转换引用须单次单向扫描，禁 pass1/pass2 两次 replace（会在已插入反引号内二次匹配产生嵌套反引号）。
6. **围栏独占一行**——``` 须独占一行，奇偶失配会让后续全文被误判为代码块。
7. **反引号嵌套冲突**——标题含内嵌反引号（`gh pr`）须改《gh pr》或降单反引号，禁双层反引号。
8. **索引表头误计**——过滤表头行（含「你要做的」）后再统计条目数，禁把表头当数据。
9. **中文分词失败**——导航测试用 2~3 字连续子串匹配，禁空格 split 中文连写。
10. **MAP 未全覆盖**——节号升级前须 100% 命中真实节标题，禁带缺失节号交付。

## 十二、信任但验证原则

完成脚本化核查后，必须另起独立脚本重新扫描目标文件，交叉印证关键指标（章连续 / 索引唯一 / 残差 0 / 围栏偶 / 导航 / 节级命中）。脚本自身可能有缺陷（提取漏 `### ` 前缀、引导动词限定漏捕、表头误计），须修正后重验，不把单次输出当结论。每次重验须记录指标数值，作为交付证据。

## 十三、执行指令（端到端 10 步）

1. **路径核验**：确认目标记忆文件路径，读取全文，列出记忆源（全局 + 各 workspace）。
2. **备份**：修改前生成 `.bak` 副本（同名 + `.bak`）。
3. **盘点与过期判定**：列每日日志时间跨度，阈值参数化（默认 30 天）。
4. **蒸馏合并**：按主题归类待蒸馏日志，提取长期事实写入/更新 `MEMORY.md`。
5. **去重结构化**：合并重复，保持单主题 < 3000 字。
6. **触发交叉引用核查专项**：若 `MEMORY.md` 含速查索引表/跨章节引用，跑本文件「交叉引用合规核查专项」六步。
7. **执行六连验证门禁**：跑本文件「六连验证门禁」六项硬指标。
8. **整改不达标项**：回本文件「交叉引用合规核查专项」步骤 2/4/5，或回本文件 8.1 节 12 条整改。
9. **复检 12 条**：按本文件 8.1 节 12 条强制要求逐条核对第 1–12 条，全部满足方可交付。
10. **清理确认（仅每日日志）**：先备份 + 显式确认，交付差异清单与六连验证数值记录。

## 十四、示例场景
