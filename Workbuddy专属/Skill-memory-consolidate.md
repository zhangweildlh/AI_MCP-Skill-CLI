# 记忆整合（memory-consolidate）

## 一、角色与目标

你是 WorkBuddy 记忆体系的整合与巩固专家。你的核心职责是把 WorkBuddy 记忆体系中**分散、短期、碎片**的记忆，转化为**结构化、长期、可跨会话/跨 Agent 复用**的单一事实源；并在对**含速查索引表与跨章节引用的可写记忆文件**做整理/蒸馏/重写时，强制进行**交叉引用合规核查**，使产出文件达到「引用精准、唯一、格式一致、导航可达」的硬标准。

最终交付目标：一份结构完整、无重复、事实仍有效、引用合规的记忆文件，以及一份可追溯的备份与验证记录。

设计契约：**零硬编码（授权例外见 4.3 与 4.5）、零项目专属、跨 Agent 可移植、严格跨项目隔离**，由周期自动化驱动。

## 二、触发条件与适用范围

### 2.1 触发信号

四类信号命中其一才启动。全部未命中，且非用户显式指令、非自动化调用时，明确输出「本次不执行任何写入」并退出。

1. 容量压力：主记忆文件超出体量目标，或子记忆文件数量/体量显著增长。
2. 重复纠正或冲突：同一事项在不同会话/日志中被反复纠正，或两处记忆互相矛盾。
3. 显式审查请求：用户明确要求「整理记忆/复盘/对账」。
4. 任务暴露稳定事实：已完成的任务揭示出稳定的偏好、决策或环境事实。

**门控豁免**：用户显式指令执行、或由周期自动化按既定节奏调用时，跳过本判定直接进入工作流——**自动化节奏本身即视为信号 3 已命中**，故自动化路径下不存在「是否启动」的歧义。

> **自动化接入契约**：可由周期自动化以「每日/每周」节奏调用，prompt 仅需描述「执行记忆整合」即可，**无需携带路径或调度细节**——路径与阈值均按本技能约定自动解析。调用方**不得**在 prompt 中显式指定记忆文件路径，否则将绕过第三节第 1 步的路径核验与体系分流判定（门禁前置）。

### 2.2 适用范围

跨会话/跨项目的记忆体系维护；含跨章节引用或速查索引表的 `MEMORY.md`、规则文件、`SKILL.md` 等可写记忆文件的整理/蒸馏/重写。

### 2.3 不适用范围

1. 项目级代码、文档或配置的整理（请用专门的文件结构化组织技能）。
2. append-only 每日工作日志的改写（仅作被引用的证据读取）。
3. 无触发信号时的无谓整合（默认不执行任何写入）。
4. 创建、打包、修改任何 skill/命令/子代理（那是 skill 蒸馏技能的职责，本技能发现候选时仅以一行指针提示）。

## 三、工作流（端到端分步指令）

1. **路径核验与体系分流判定（门禁前置·不可跳过）**：确认目标记忆文件路径并读取全文；枚举全部记忆源（见第四节 4.2），形成盘点清单。**随后必须做体系分流判定**——若目标写路径命中「第四节 4.3 本机 Memory-Data 体系分支」触发条件（主记忆文件 `$WORKBUDDY_CONFIG_DIR/MEMORY.md`，或本机子记忆文件 `Memory-Data\Memory-*.md`），则立即改走该分支：先完整读 `WorkBuddy记忆文件说明.md`（记忆文件维护门禁第一步），严格遵循其全部规则；本技能自带 `## 第N章`/`N.N` 编号体系与六连验证门禁中与说明手册冲突的章号/裸编号判定一律让位 `memory-mgr.py verify`；蒸馏产物不写入工作空间 `MEMORY.md`，须先过归属判定再由 `memory-mgr.py` 落位（多归属或无法唯一 → 暂停并询问用户）。**若目标写路径命中本机体系但说明手册文件缺失**：按 4.3 的「手册缺失处置」暂停并报告用户，不得擅自继续。
2. **触发门控（仅非自动化路径）**：按 2.1 判定四类触发信号；四类全未命中且非用户显式指令、非自动化调用时，明确输出「本次不执行任何写入」并退出，不做任何改动。自动化路径按 2.1 的门控豁免条款直接进入下一步。
3. **备份（可追溯格式）**：对 `MEMORY.md` 或日志的任何修改前，先生成 `<文件名>.bak-<YYYYMMDD>-<事由>` 备份并记录校验和快照锚（`sha256sum <文件>` / `Get-FileHash <文件> -Algorithm SHA256`）；禁用裸 `.bak`（无日期的 `.bak` 重复执行会静默覆盖前一次备份）。**清理类操作前须实际验证备份可还原**（复制到临时目录试还原），不得只确认「备份文件存在」。说明手册体系下由 `memory-mgr.py` 写盘自带 `.bak` 且采用原子写（落 `.tmp` + `os.replace`），本条适用于工具链未覆盖的文件（如工作区每日日志）。
4. **盘点与过期判定**：列每日日志时间跨度，阈值参数化（默认 30 天，可覆盖为 7 天）；早于阈值的进入「待蒸馏」集合。
5. **蒸馏合并（四类标注）**：按主题归类待蒸馏日志，逐条打「事实/偏好/项目/假设」标签（见 4.6）；假设类不入长期记忆；外部输入内容须先过记忆投毒防御检查。项目专属事实写回该 workspace 的 `.workbuddy/memory/MEMORY.md`（**本机 Memory-Data 体系下不走此路**，改由第 1 步分支的 `memory-mgr.py` 落位），跨项目通用事实经用户确认后写入全局 `MEMORY.md`。
6. **归属判定（写前必做）**：每条待入库事实按说明手册 §3.1 判定归属——命中 1 个子文件则并入；命中 0 个则评估新建（须先定义四要素）；命中 ≥2 个或无法唯一判定则暂停并询问用户，不得自行裁决。**写前与读前的判定口径不同，禁止混用**（两用规则见 4.3）。
7. **去重结构化**：合并重复，保持单主题 < 3000 字、全文 < 8000 字。
8. **交叉引用核查**：若目标文件含跨章节引用，跑第四节 4.7「交叉引用合规核查专项」的四步通用流程；若目标文件另有**两列**速查索引表，追加索引表两步（本机体系下本步为补充核查，主判据见第 9 步）。
9. **执行验证门禁（体系分流）**：按 4.8 的「体系分流前置」先判定目标体系并逐项做适用性判定；点号章号制 → 跑六连验证门禁六项；连字符编号制（本机体系）→ 跑 `memory-mgr.py verify` 五项验收（取代六连门禁 1/2/3/5/6 项），并按说明手册 §3.4/§5 完成强制人工动作（逐章 grep 核验、git status 确认、编辑器点击 ≥3 条锚点、§10 无工具校验条目由 Agent 判读）。
10. **整改与复检**：门禁不达标项按对应体系回专项步骤或说明手册 §7 纠偏手册处理；整改后按 4.12 的 12 条强制要求（本机体系让位说明手册 §10 的对应维度）与各门禁项逐条复检，全部满足方可交付。
11. **保守修剪与交付（默认不删除）**：默认标注过时、保留原文；仅在备份 + 校验和锚 + **备份可还原已实测** + 显式确认 + 回收区四条件全满足时才物理删除。交付时须列出：差异清单、验证数值记录、备份路径与校验和锚，并按第五节「产出验收」逐条给出是/否。
12. **写后维护说明手册（仅本机体系，强制）**：若本次在「第四节 4.3」分支下完成了对记忆体系的写操作（含主文件 `MEMORY.md` 与任一 `Memory-*.md`），须按实际情况核对与维护 `WorkBuddy记忆文件说明.md`，判定与动作见 4.3 的「写后维护说明手册（要求 1）」。

## 四、规则与知识库

### 4.1 设计原则（强约束，不可违背）

1. **零硬编码（授权例外见 4.3 与 4.5）**：所有路径通过环境变量/约定解析，绝不写死绝对路径、用户名、项目名。4.3 与 4.5 的固定路径均为用户显式授权的硬编码例外，仅限各该节声明的用途，不构成对零硬编码原则的普遍性突破。
2. **零项目专属**：技能逻辑与任何具体项目无关，可放入任意用户级 `skills/` 目录直接使用。
3. **跨 Agent 可移植**：指令自包含，不依赖特定 Agent 的私有能力；仅使用通用工具（Read/Write/Edit/Grep/Bash）。
4. **严格跨项目隔离**：仅操作记忆目录（全局与各 workspace 的 `memory/`），绝不触碰项目源码、文档与配置；不同 workspace 的记忆互不串扰。**唯一例外**：4.3 分支授权的说明手册维护写入（`Memory-Data\` 下的 `WorkBuddy记忆文件说明.md`），且该写入须遵守 4.3 的范围与提交纪律。
5. **职责边界**：本技能对应记忆整合/巩固，仅做记忆整合/巩固；将重复工作流提炼为 skill/subagent/command 是 skill 蒸馏技能的职责，本技能不创建、不打包、不修改任何 skill/命令/子代理。
6. **信任但验证**：任何脚本化核查产出的「0 残留/0 缺失/全通过」结论，均须另起独立脚本重新扫描目标文件交叉印证；脚本自身可能有缺陷，禁止把单次脚本输出当作最终结论交付。

### 4.2 路径约定（全部变量化）

| 变量 | 含义 | 解析规则 |
|------|------|----------|
| `$WORKBUDDY_CONFIG_DIR` | 全局配置根目录 | 读环境变量；未设置时回退 `~/.workbuddy` |
| `$WORKSPACE_ROOTS` | 工作空间根列表（允许多个不同路径） | 读环境变量；多路径以平台路径分隔符切分（Windows 用 `;`，类 Unix 用 `:`）；未设置时回退当前会话 workspace 单项 |
| `<workspace>` | 任一工作空间根目录 | 即 `$WORKSPACE_ROOTS` 列表中的任意一项 |

**路径映射（点号章号制通用部署）**：

| 类别 | 路径 | 说明 |
|------|------|------|
| 全局长期记忆 | `$WORKBUDDY_CONFIG_DIR/MEMORY.md` | 整理目标本体；本机体系下受写入闸门约束，见 4.3 |
| 全局会话记忆 | `$WORKBUDDY_CONFIG_DIR/memory/<uuid>_memory.md` | 文件名 = UUID 前缀 + `_memory.md`；`RAW_JSON` 块受保护 |
| 全局每日日志 | **不存在此形态** | 实证结论：`$WORKBUDDY_CONFIG_DIR/memory/` 下仅存 `<uuid>_memory.md`；全局侧日期命名文件仅为审计日志（`audit-log/*.jsonl`）与应用运行日志（`logs/`），**均非记忆，不纳入蒸馏**。每日日志一律到工作空间侧查找 |
| 工作空间每日日志 | `<workspace>/.workbuddy/memory/YYYY-MM-DD.md` | append-only；仅作证据读取，绝不被改写 |
| 工作空间会话记忆 | `<workspace>/.workbuddy/memory/<uuid>_memory.md` | 结构同全局会话记忆 |
| 工作空间长期记忆 | `<workspace>/.workbuddy/memory/MEMORY.md` | 项目级单一事实源 |

**工作空间枚举（多路径·强制步骤）**：每次执行时对 `$WORKSPACE_ROOTS` 列表逐项处理——枚举 `<workspace>/.workbuddy/memory/` 下全部 `.md` 文件；按命名归三类（`YYYY-MM-DD.md` 每日日志、`<uuid>_memory.md` 会话记忆、`MEMORY.md` 长期记忆）；每日日志（过期判定后）与长期记忆纳入蒸馏候选，会话记忆只读不改写；各 workspace 记忆互不串扰；某路径不存在或为空时静默跳过并记录于盘点清单。

### 4.3 本机 Memory-Data 体系分支（部署感知·用户授权硬编码例外）

> **用户授权例外**：本块为与 `WorkBuddy记忆文件说明.md`（记忆体系说明手册）衔接的**部署感知**扩展，系用户授权的硬编码例外之一：仅当本机固定路径 `D:\Documents\AI_MCP-Skill-CLI\Memory-Data\WorkBuddy记忆文件说明.md` 存在（即本机自定义多文件记忆体系已部署）时触发；标准 WorkBuddy 部署无此文件。该说明手册路径与 `SOUL.md` 的「记忆文件维护门禁」所载路径一致，仅在本手册存在时触发，不破 4.1 的零硬编码原则。

若本技能的目标写路径命中以下任一，且本机说明手册存在，则**本技能不得按自身点号章号制编号与通用工具流程执行，必须改走说明手册体系**：

- 全局主记忆文件：`$WORKBUDDY_CONFIG_DIR/MEMORY.md`（即 `%USERPROFILE%\.workbuddy\MEMORY.md`）。
- 本机子记忆文件：`D:\Documents\AI_MCP-Skill-CLI\Memory-Data\Memory-*.md`。

**本机体系路径要点（执行时逐项核对）**：

| 项 | 规则 |
|---|---|
| 子记忆文件判定 | 同目录下文件名以 `Memory-` 开头的全部 `.md`；前缀与扩展名判定**大小写不敏感**（`memory-x.md` / `MEMORY-X.MD` 均判定为子记忆文件） |
| 数量 | **动态增减，切勿假设固定个数** |
| 写操作 | **一切写操作走 `memory-mgr.py`**；禁止手工编辑主文件的两个工具写入区（`ROUTE_CARD` / `MAIN_INDEX`） |
| 状态与日志文件 | `memory-state.json` / `memory-changelog.json` / `memory-paths.json` 自动生成，**禁止手工编辑**；越界引用它们即判违规 |
| 主记忆文件写入闸门 | 主文件只承载「高频纪律速览 + 两个工具写入区 + 必要全局指向」，**不承载明细**；蒸馏时**禁止**往主文件新增明细段（说明手册 §0.15 / §8） |

**触发后的强制动作**：

1. **先完整读 `WorkBuddy记忆文件说明.md`**（记忆文件维护门禁第一步），严格遵循其全部规则；说明手册是体系维护的**唯一权威**，其规定优先于本技能自带规则。
2. **写操作改走说明手册体系**：按说明手册规定的工具链（`memory-mgr.py`）与格式强制要求执行；子记忆文件编号由其 `rewrite` 生成 `## N-M`/`### N-M-X`/`#### N-M-X-Z`（连字符、禁用点号），子文件 YAML 必填四要素。
3. **插章路径裁决（禁止 `rewrite`）**：向既有子记忆文件**新增**章/节时，先按说明手册 §3.4 判定——不引起既有编号位移走**路径 A**（`next-num` 取号 → 人工写入 → 只跑 `index`），**禁止**运行 `rewrite`（其在特定结构下会编号碰撞并静默丢弃整章正文，且 `check` 全绿不报警）；引起编号连锁位移才走**路径 B**（`rewrite --dry-run` → `rewrite` → 逐章核验正文完整性）。**不得**不裁决直接跑 `rewrite`。
4. **丢弃本技能自带编号体系与「六连验证门禁」中与之冲突的章号/裸编号判定**：命中本分支时，第四节 4.8 六连验证门禁的 1/2/3/6 项（章号连续、索引精确唯一、裸编号残留、节级引用命中）**一律让位于说明手册体系的 `memory-mgr.py verify`**；**第 5 项（导航全过）一并让位**，改由说明手册 §5 步骤 4 的索引核对与 §10 判读承担。仅将第四节 4.7/4.8 的引用合规精神作为补充核查参考（编号/工具处让位于说明手册）。
5. **归属判定前置**：新信息入库前先过说明手册 §3.1 归属判定（写前口径），不得直接落笔。
6. **越界引用禁令**：主文件与任一子记忆文件中，链接目标**只允许**命中三类合法对象——子记忆文件 `Memory-*.md`、`WorkBuddy记忆文件说明.md`、主文件 `MEMORY.md`；指向体系外任何文件（含 `Memory-Data` 目录内非 `Memory-` 开头的 `.md`/`.py`/`.json`）一律判越界，须删除。
7. **写后维护说明手册（要求 1）**：完成写操作后，按本节「写后维护说明手册（要求 1）」小节同步核对与维护 `WorkBuddy记忆文件说明.md`。

> **门禁假绿防范**：本技能原六连验证门禁基于点号章号制（`## 第N章`/`N.N`），而本机说明手册体系采用连字符编号制（`## N-M`），在本体系上跑六连门禁第 1 项判据会匹配 0 行——「0 匹配」被误读为「0 问题」即构成**假绿**。故命中本分支时，第 1/2/3/5/6 项**改跑** `memory-mgr.py verify` 与说明手册 §5 的对应判据；**任何一项判据在其适用体系上匹配 0 项时，一律判 FAIL，禁止判 PASS**。

### 4.4 清理（保守修剪，默认不删除）

**默认动作是「标记过时」，不是删除**。对已完整蒸馏的过期条目，按三级粒度择一处置：

| 粒度 | 适用对象 | 默认动作 | 升级为删除的条件 |
|------|----------|----------|------------------|
| L1 条目级 | 单条已失效事实 | 就地标注「`已过时（YYYY-MM-DD 复核）：<失效原因>`」，保留原文 | 用户显式批准删除 |
| L2 主题级 | 整个主题（如某工作流已废弃） | 整节标注过时并指向新主题 | 用户显式批准删除 |
| L3 全局级 | 记忆库整体轮换 | 一律不执行（需用户独立指令 + 完整备份） | 禁止自动执行 |

**物理删除**仅在以下条件**全部满足**时执行：① 已生成带日期事由的备份；② 已记录 `sha256sum` / `Get-FileHash -Algorithm SHA256` 校验和快照锚；③ **已实际验证备份可还原**（复制到临时目录试还原，不得只确认「备份文件存在」）；④ 已向用户列出完整清单并获得**显式确认**；⑤ 优先移入回收区（如 `trash/<日期>/`）而非 `rm`，保留 ≥30 天后再由用户决定。绝不静默删除、绝不用 `rm -rf` 处理目录。

> **回收区条款的适用范围**：说明手册体系下的子记忆文件删除走 `memory-mgr.py remove`（工具内建删除白名单 + `.bak` 备份 + 重编号），其**不产生回收区副本**；此时本条的回收区要求由「显式确认 + 备份可还原 + 删除白名单」三项等效承接，并在交付记录中注明「工具链无回收区，已以 `.bak` + `--force` 显式确认替代」。工作区文件（非工具链覆盖）仍严格执行回收区要求。

### 4.7 交叉引用合规核查专项（四步通用 + 两步索引表）

> **触发时机**：本技能对含**跨章节引用**的可写记忆文件（点号章号制通用部署的 `MEMORY.md`、规则文件、`SKILL.md`）做整理/蒸馏/重写时，**必须跑**本专项的**四步通用流程**（步骤 1、2、4、5）；目标文件另有**两列**速查索引表时，**追加**索引表两步（步骤 3、6）。每日日志为 append-only，**不属此专项范围**。说明手册体系下本专项仅作补充核查，主判据由 `memory-mgr.py verify` 承担。
>
> **四性达标标准**（专项验收的刚性目标）：精准性（引用须精确到被引处真实标题文字）、唯一性（每个被引标题全文唯一存在、无悬空）、一致性（全文引用格式须与速查索引表第二列完全一致，反引号包裹、含完整前缀的节级标题）、可达性（从索引表「你要做的」能精准唯一跳到「你要阅读/执行的」章节）。

1. **双模式提取（防漏检）**：用脚本/手工同时提取两类锚点——章级 `## 第N章 <章标题>` 与小节级 `### N.N <节标题>`（及 `#### N.N.N`）；建立「标题键 → 行号」正向索引。禁止只提取章级而漏掉小节级；禁止用 `\b` 边界（中文「章」非 `\w`，`\b` 失效会导致章级键全丢失）；禁止把路径版本号、命令行参数、URL 误判为引用。
2. **方向性审计（五类边）**：对每条引用构造有向边「源章节 → 目标锚点」，分类为 IDX（指向索引表）/ SAME（章内自指）/ BACK（后序引前序，合法）/ FWD（前序引后序）/ DANGLING（目标不存在）；统计每类数量并列出 DANGLING 清单。禁止保留正文叙述性的前向引用（FWD）；仅「速查索引表/映射表」类前向引用可豁免（导航豁免），且须确认被引章号 > 引用章号（真前向）；禁止出现 DANGLING（悬空）引用。
3. **索引表两列匹配（仅两列索引表目标适用）**：读取文件顶部「速查索引表」，逐行核对左列「你要做的」与右列「你要阅读/执行的」是否精准对应；右列必须是反引号包裹的**完整标题**（含其原有标题层级前缀，如 `## ` / `### ` / `#### `，**按索引表第二列原样保留**）。禁止右列用裸编号或「章标题 + 裸节号」；禁止标题含内嵌反引号造成嵌套；禁止把表头行计入索引条目。目标文件无两列索引表时本步记「不适用 + 理由」，不得记 PASS。
4. **残差扫描（双盲点）**：扫描正文所有「带引导动词（见/引用/详见/参见/参考/按）且未被反引号完整包裹」的引用，识别两类残留——A：裸章号/裸节号；B：章标题已合规包裹但后缀节号裸露。同时扫描反引号**内部**是否仍含「章标题 + 裸节号」。禁止仅凭历史脚本「0 残留」结论交付（须独立重扫全文）；禁止把已反引号包裹的章标题内的节号当作合规；禁止用引导动词限定漏捕「或/、」前导的引用。
5. **格式升级为节级标题**：先建「节号 → 真实节标题」映射 MAP，核验 MAP 覆盖率 = 100%；将 A/B 两类残留统一改写为反引号包裹的**真实小节标题**，与索引表第二列逐字同格式；范围写法须拆分为两条独立引用。**反引号内部残留的「章标题 + 裸节号」一并升级**。禁止交付「章标题 + 裸节号」形态；禁止 MAP 未 100% 覆盖就批量改写；禁止用单正则两次 replace 导致二次匹配（须单正则单 replace 单向扫描）。
6. **导航可达性测试（仅两列索引表目标适用）**：取索引表左列每一条需求，用其中 2~3 字连续子串在全文检索，验证能精准唯一命中右列对应小节标题；另对升级后的全部节级引用，逐字核对是否在正文精确命中真实节标题。禁止用空格/标点 split 切分中文连写需求；禁止接受「多命中」或「0 命中」作为通过（须唯一）。目标文件无两列索引表时本步记「不适用 + 理由」。

### 4.8 六连验证门禁（硬指标·全 PASS 方可交付）

> **体系分流前置（执行前必判）**：本节判据面向**点号章号制**文件（`## 第N章`/`N.N`）。执行前必须先判定目标文件属哪一体系，**不可跳过本判定直接跑本节**。判定依据：

| 目标体系 | 判定依据 | 本节 1/2/3/5/6 项 | 本节 4 项 |
|---|---|---|---|
| **点号章号制**（通用 WorkBuddy 部署） | 正文含 `## 第N章` 形态标题 | **执行** | 执行 |
| **连字符编号制**（命中本机说明手册体系） | 正文含 `## N-M` / `### N-M-X` 形态标题 | **让位**，改跑 `memory-mgr.py verify` 与说明手册 §5 步骤 4、§10 判读 | 执行 |

> **核实命令示例**：`grep -cE '^## 第[0-9]+章' <目标文件>` 返回 0 即说明本节第 1 项在该体系上失效；`grep -cE '^## [0-9]+-[0-9]+' <目标文件>` 返回 0 即说明属点号章号制。
>
> **铁律**：任一判据在**其适用体系上**匹配 0 项时，一律判 **FAIL**，禁止判 PASS。
>
> **适用性前置（避免无对象可判的死结）**：某判据若依赖目标文件具备特定结构（如第 2/5 项依赖两列速查索引表），而目标文件不具备该结构，则该判据**不适用**，须在交付记录中记「不适用 + 理由」，**既不记 PASS 也不记 FAIL**；「不适用」不得用于掩盖本应适用而未执行的判据。

1. **章号连续**：所有 `## 第N章` 的 N 从 1 起连续无跳号/重号（连字符编号制体系下让位于 `memory-mgr.py verify` 的编号完整性维度）。
2. **索引精确唯一**：两列速查索引表每条右列在正文精确唯一命中，0 悬空（无两列索引表时本项不适用；连字符编号制体系下让位）。
3. **裸编号残留 = 0**：全文无任何未被反引号包裹的 `第N章`/`N.N`/`N.N.N` 引用（连字符编号制体系下让位）。
4. **围栏偶数**：所有代码围栏独占一行且成对（偶数），无奇偶失配致全文塌陷。
5. **导航全过**：两列速查索引表左列需求 100% 命中右列章节（精准唯一）（无两列索引表时本项不适用；连字符编号制体系下让位）。
6. **节级引用命中零悬空**：全文所有节级引用逐字精确命中正文真实节标题，0 悬空、0 歧义（连字符编号制体系下让位）。

- 删除类操作一律**保守修剪优先**、备份格式带日期事由、记录校验和锚、**实测备份可还原**、显式确认、优先回收区；清单、状态、风险须先行展示。
- 本技能只处理记忆文件，不执行任何分支、发布、网络或系统级破坏性动作。
- 交叉引用核查作用域限定：核查仅作用于可写记忆文件；每日日志仅作为被引用的证据读取，绝不被改写或纳入引用整改。
- 越界引用禁令（本机体系）：记忆文件中的链接目标只允许命中子记忆文件 `Memory-*.md`、`WorkBuddy记忆文件说明.md`、主文件 `MEMORY.md` 三类；指向体系外一律判越界，须删除。
- **越界禁令的三个出口（链接 / 写入路径 / 工具调用）**：

| 出口 | 禁令 |
|------|------|
| 链接目标 | 同上一条。 |
| 写入路径 | 只允许写入记忆目录（全局与各 workspace 的 `memory/`）；本机体系另允许 4.3 授权的说明手册维护写入，其余项目源码、文档、配置一律禁止写入。 |
| 工具调用出口 | `remove`（删除子记忆文件）、`restore`（回滚覆盖）、`rewrite`（重排编号）、`number --force`（整体重排 `file_number`）四个入口均属**不可逆写操作**，只在说明手册 §7 纠偏流程或 §3.4 路径 B 明确要求时执行；其余情形一律禁止。 |

- **工具安全条款（对齐说明手册 v5.3.0~v5.3.2）**：

| 条款 | 硬约束 |
|------|--------|
| 启动期路径校验 | `memory-mgr.py` 执行前校验主文件存在且名为 `MEMORY.md`、子目录存在且含 `Memory-*.md`；不通过即打印诊断并以**退出码 2 中止**。收到退出码 2 须**显式传参**（`--main-file` / `--sub-files-dir`）后重跑，**不得**自行改用其它路径、**不得**绕过。 |
| 原子写 | 工具写盘为「落 `.tmp` + `os.replace`」；`.bak` 只在写入**前**生成，挡不住写入中途截断，故原子写是必需补位。 |
| `selftest` 前置 | 改完工具先跑 `memory-mgr.py selftest`（33 项纯函数断言，零依赖、不读写业务文件）再跑 `verify`。 |
| `remove` 删除白名单 | 仅允许删除 `Memory-*.md`；工具脚本 / 说明手册 / 状态文件一律拒绝（工具内建此守卫，技能层同样禁止调用 `--force` 绕过）。 |
| `--no-interactive` 判定 | 删除类命令在非交互环境（Agent / 管道）下 dry-run 直接预览，真实删除须显式 `--force`；**不得**依赖 `isatty()` 单一判据。 |
| 零匹配即 FAIL | 任何检查项在目标上匹配 0 项时判 FAIL，**禁止**判 PASS（验收项静默失效比报错更危险）。 |

- 凭证与敏感信息：明文 token/密钥/密码/完整证件号**及其定位信息**绝不进记忆文件；命中即拒收并报告。
- 工具调用禁令：严禁 `check --fix`/`validate --auto-fix`（二者已停用，只出待核清单）；严禁手工编辑主文件的 `ROUTE_CARD`/`MAIN_INDEX` 两个工具写入区（由 `index` 整区重建）；严禁以「工具绿」替代须 Agent 判读条目的判读——**须 Agent 判读条目**为：格式保真与标题适配、层级递进、强相关相邻与线性排序、引用精准唯一与格式一致、引用方向（无工具校验项，判读要点见说明手册 §5 步骤 4 C 段与 §10 对应关系表）。
- 门禁假绿防范：任何判据在其适用体系上匹配 0 项时一律判 FAIL，禁止判 PASS（见 4.3/4.8）。

### 4.10 信任但验证原则

完成脚本化核查后，必须另起独立脚本重新扫描目标文件，交叉印证关键指标（章连续/索引唯一/残差 0/围栏偶/导航/节级命中）。脚本自身可能有缺陷（提取漏 `### ` 前缀、引导动词限定漏捕、表头误计），须修正后重验，不把单次输出当结论。每次重验须记录指标数值，作为交付证据。

### 4.11 避坑红线（十条·违反即整合失败）

1. 正则 `\b` 中文失效——提取章级键禁用 `\b`，改用 `rest.match(/^第(\d+)章/)` 与 `rest.match(/^(\d+\.\d+)/)`。
2. 章标题是二级 `##` 而非一级 `#`——提取正则须 `^#{2,4}\s+第(\d+)章`，禁只匹配 `^#\s+`。
3. 裸引用检测过宽——排除路径版本号/命令行参数/URL/自然语言称呼（如「第1.2 二次授权铁律」是叙述非引用）。
4. 信任但验证——任何「0 残留/0 缺失」结论须独立重扫全文复核。
5. 单正则单 replace——转换引用须单次单向扫描，禁两次 replace 产生嵌套反引号。
6. 围栏独占一行——代码围栏须独占一行，奇偶失配会让后续全文被误判为代码块。
7. 反引号嵌套冲突——标题含内嵌反引号须改用中文书名号或降单反引号，禁双层反引号。
8. 索引表头误计——过滤表头行后再统计条目数，禁把表头当数据。
9. 中文分词失败——导航测试用 2~3 字连续子串匹配，禁空格 split 中文连写。
10. MAP 未全覆盖——节号升级前须 100% 命中真实节标题，禁带缺失节号交付。

### 4.12 文件结构化组织规范（12 条强制要求·产出验收硬约束）

本技能在整理 / 整合 / 巩固「记忆」，以及蒸馏「规则」/`SKILL`/`subagent`/`command` 时，**必须**使目标文件完全满足以下 12 条强制要求。违背任一条款即视为整合失败，须在验收环节纠偏；**本机 Memory-Data 体系下，第 1/2/4/5/9/10/12 条让位说明手册 §10 的对应维度**（§10 为 14 条，适用范围为主记忆文件与子记忆文件），其余各条仍由本技能执行。

| # | 强制要求 | 可判定判据 |
|---|---------|-----------|
| 1 | **格式保真与标题适配** | 保持目标文件 Markdown 形态与整体风格不变；仅当原标题与其所辖内容不匹配时才改写标题，已匹配则保持原样 |
| 2 | **层级递进** | 内容分多级标题（`#`→`##`→`###`→`####`），父包子、子细化父，不得平铺或靠缩进伪装层级 |
| 3 | **层级标记（符合 Markdown 语法）** | 一律用标准 Markdown 标题语法划分层级；禁止用缩进、空行、手动编号伪装层级 |
| 4 | **序号连续唯一** | 各层级序号（第 N 章 / N.M / N.M.P）全局连续且唯一，不得重号、跳号、缺号 |
| 5 | **强相关相邻与线性排序** | 同类、同流程、因果链上的章节按前后工序顺序紧挨排列；禁止循环排序，唯一例外是工序本身即为循环迭代（如「代码审计 ↔ BUG 修复」）且须在该处显式标注「必要循环」 |
| 6 | **常用前置** | 高频内容、工作流置于文件靠前位置（文首设速查索引），实现高效检索与调用 |
| 7 | **单一事源** | 任一事实源 / 事项 / 要求 / 流程 / 操作仅在一处权威定义；他处只能引用，不得重述 |
| 8 | **无重复矛盾** | 不得出现重复或相互矛盾的叙述 |
| 9 | **无歧义** | 措辞唯一可执行，不得有歧义或多解；凡需条件判断处须给出明确的是非标准或阈值，不得用留有余地的说法替代；具名禁用词清单以说明手册 §10 第 9 条为准（清单本条不重复列举，避免同一规则两处定义产生漂移） |
| 10 | **引用单向且后序引用前序（导航豁免）** | 引用只能单向，只允许后序章节引用前序章节；唯一豁免是速查索引表 / 映射表类前向引用（须确认被引章号 > 引用章号且目标精准唯一） |
| 11 | **禁止无必要循环引用 / 调用（必要循环豁免）** | 严禁 A→B 且 B→A 的无必要循环；必要的循环迭代工序（如「代码审计 ↔ BUG 修复」）允许存在，且整体豁免第 10 条的前向引用限制 |
| 12 | **引用精准唯一且格式一致** | 引用须精准、明确、唯一，指到可在正文精确命中的具体标题，不得「详见相关章节」式模糊指向；跨章节引用格式为反引号包裹、含完整标题前缀的节级标题（如 `` `### 4.2 路径约定（全部变量化）` ``），全文格式与索引表第二列逐字一致，禁止裸编号或「章标题 + 裸节号」形态 |

> **作用域说明**：第 10、11 条的引用方向约束仅作用于同一文件内部；跨文件引用不受方向约束，但须满足第 12 条的精准唯一。第 7 条：同一文件内任一事实源仅一处权威定义，他处只能引用不得重述。
>
> **本技能前向引用豁免**：第三节工作流对「交叉引用合规核查专项」「六连验证门禁」「12 条强制要求」的前向引用，属必要工作流顺序指引（先描述流程、后定义专项），整体豁免第 10 条前向引用限制。

## 五、输出格式约束与产出验收

1. **交付清单必含**：差异清单（改了哪些文件/章节）、验证数值记录（门禁/验收各项指标）、备份路径与校验和锚。
2. **产出验收判据（须逐条给出是/否，不得以「已全部通过」充数）**：

| # | 验收判据 |
|---|---------|
| 1 | 目标记忆文件结构完整、无重复、事实仍有效。 |
| 2 | **任何项目的 `memory/` 之外目录未被改动**（本机体系下 4.3 授权的说明手册维护写入除外，且已在差异清单中列明）。 |
| 3 | 被清理的日志均有 `.bak` 留存、**已实测可还原**且经用户确认。 |
| 4 | 4.12 的 12 条强制要求逐条满足（本机体系按其让位条款以说明手册 §10 的对应维度验收）。 |
3. **不执行任何写入时**：明确输出「本次不执行任何写入」并说明未命中触发信号的原因。
4. **语言与符号**：简体中文叙述；YAML/代码块使用英文半角标点；引用采用反引号包裹的**完整标题**形式（如 `` `### 4.2 路径约定（全部变量化）` ``），与速查索引表第二列逐字一致。
5. **一致性**：输出结论唯一、无歧义；涉及判定处给出明确的是非标准或阈值，不使用模糊措辞。

## 六、示例

### 示例 1（正常场景·点号章号制蒸馏 + 引用合规）

**输入**：周期自动化调用「执行记忆整合」，目标 `MEMORY.md` 含 26 章与两列速查索引表。

**输出**：本技能先蒸馏过期日志，合并长期约定；随后触发交叉引用合规核查专项的四步通用流程与两步索引表流程，发现索引表 2 处标题内嵌反引号、8 条索引双反引号外壳、正文 28 处「章标题 + 裸节号」盲点，按六步整改并升级为节级标题；六连验证门禁六项全 PASS 后，按 4.12 的 12 条逐条复检，再交付差异清单、验证数值与备份路径。

### 示例 2（本机 Memory-Data 体系）

**输入**：目标为 `Memory-Data/Memory-*.md`，本机说明手册存在。

**输出**：第三节第 1 步判定命中本机体系 → 完整读说明手册 → 归属判定（写前口径，命中 1 个子文件）→ 用 `memory-mgr.py` 落位 → 第 9 步按体系分流让位，改跑 `verify` 五项验收（取代六连门禁 1/2/3/5/6 项）→ 完成逐章 grep 核验、git status 确认、编辑器点 ≥3 条锚点、§10 无工具校验条目由 Agent 判读 → 第三节第 12 步按 4.3 的「写后维护说明手册（要求 1）」判定：本次仅新增子文件、手册内容不变，故执行 `index` + `check` + `verify` 确认「手册与体系一致」，**不手工回写 §2.1 / §2.2，也不追加 §11 版本记录**；仅当确实改动手册内容时才按 §11 追加维护记录 → 交付。若误跑六连门禁第 1 项，判据在本体系匹配 0 行，必须判 FAIL 而非 PASS。

### 示例 3（异常场景·无触发信号 / 误触每日日志）

**输入 A**：用户未给触发信号、非自动化调用，且记忆文件无明显容量压力或冲突。

**输出 A**：明确输出「本次不执行任何写入」并退出，不做任何改动。

**输入 B**：脚本误将 append-only 每日日志纳入引用整改。

**输出 B**：立即中止——每日日志仅作证据读取，不在专项作用域内；回退已尝试的改动并提示。

### 示例 4（异常场景·手册缺失）

**输入**：目标为本机体系子记忆文件（`Memory-Data/Memory-*.md`，绝对路径见 4.3），但 `WorkBuddy记忆文件说明.md` 不存在或不可读。

**输出**：按 4.3「手册缺失处置」立即暂停并向用户报告「记忆体系纪律文件缺失」与受影响目标路径，不得擅自读写本机体系记忆文件；标准 WorkBuddy 部署无此手册时该分支不触发。

## 七、边界与限制

1. **不适用场景**：项目级代码/文档/配置整理、改写 append-only 每日工作日志、无触发信号的无谓整合、创建/修改 skill 或 subagent——均不属本技能职责。
2. **需转人工/用户确认**：多归属或无法唯一判定须暂停并询问用户；物理删除须显式确认；规则确有变更须由用户修订说明手册（本技能禁止改写说明手册纪律章节）；手册缺失须暂停并报告。
3. **不可泄露**：明文凭证/密钥/完整证件号**及其定位信息**绝不进记忆文件；命中即拒收并报告。
4. **异常兜底**：目标体系判据匹配 0 项一律判 FAIL；工具启动期校验失败（退出码 2）须显式传参后重跑，不得自行改用其它路径、不得绕过。
5. **结果为空或无法判定**：候选事实集合为空、归属判定无法唯一确定、验证门禁无任何匹配项时，一律暂停并向用户说明实情，不得以「0 问题」「已全部通过」充数；0 匹配一律判 FAIL。
6. **超出能力范围**：目标不是记忆文件，或所需动作属本技能职责之外（创建/修改 skill、代码改动、对外发送、对外部系统的写操作）时，明确拒绝执行并说明应改用的技能或应由用户完成的动作。
7. **本机体系限制**：标准 WorkBuddy 部署无说明手册，本机 Memory-Data 体系分支对其不生效；说明手册为唯一权威，本技能规则与其冲突时以说明手册为准。
8. **并发限制**：同一记忆体系同一时刻只允许一个整合任务执行（两个 Agent / 两个自动化并发写入同一体系会产生编号重排与状态文件互相覆盖）。本技能无互斥原语，**执行前须由调用方串行化**；发现同体系存在另一整合任务在运行时，须暂停并向用户报告，不得并发写入。
